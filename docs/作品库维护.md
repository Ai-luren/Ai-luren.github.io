# 作品库维护

`src/data/projects.js` 是首页精选和 `works.html` 全部作品页的唯一作品数据源。

- 新作品加入 `PROJECTS`，使用唯一 `id` 和真实封面、标题、奖项。新增作品通常设置 `featured: false`；首页只取前 8 件精选，保持现有两页手机手势。
- `category` 使用 `commercial`（商业广告）、`short-film`（创意短片）、`social`（社媒与 UGC 广告）、`visual`（视觉实验）。文旅宣传片归入商业广告。按真实属性填写；当前 15 件作品分别为 7 / 3 / 3 / 2 件。
- 每件作品只有一个实际播放地址 `videoUrl`，由 `videoSource(本地相对路径, ImageKit 地址)` 生成。Vite 开发模式始终从 `assets/videos/works/` 加载本机 MP4（不访问 ImageKit），正式构建则使用配置的 ImageKit HTTPS 原片地址；未配置 ImageKit 地址时正式网站显示待上传。不得将测试流量导向 ImageKit。不要填写 API Key、签名密钥或平台网页地址。
- 播放器优先使用 `src/data/project-video-metadata.json` 预登记的真实显示宽高计算尺寸，`loadedmetadata` 只核对规格；缺少规格时先使用稳定占位再读取实际比例。视频使用 `object-fit: contain`，不按封面比例推断，也不为同一作品切换不同画幅。
- 原平台链接保留在 `sourceUrl` 供资料溯源，作品点击不会跳到原平台。
- `caseStudy` 暂为 `null`。以后有真实资料时可扩展为 `{ summary: { zh, en }, client, year, credits: [], stills: [] }`；本轮未实现案例详情页。

Vite 使用 `index.html`、`works.html` 两个正式构建入口，保留相对构建路径；无需新增 Netlify 重写或路由框架。

验证：`npm run build`、`npm run check:media-safety`、`npm run check:i18n`、`node scripts/check-project-library.mjs`、`git diff --check`。
作品库检查默认访问 Vite 生产预览 `http://127.0.0.1:5181/`，可通过 `PORTFOLIO_URL` 指定其他预览地址。移动端既有回归脚本也支持该环境变量。

## 当前本地素材

- 本地归档有 15 条 MP4，对应当前作品库的 15 件作品；岳阳楼只保留在商业广告分类一次。它们被 `.gitignore` 排除，不进入 GitHub 提交或正式构建。
- 现有 8 件精选封面、标题、奖项不变。新增 7 件作品使用原片截帧，保存在 `assets/images/project-covers/library/`，不编造奖项；无奖项时卡片显示真实分类。新封面完整显示，不强制裁切。
- 目录名 `AI Short Flims` 保留原样，代码引用与磁盘实际名称一致。视觉实验按用户指定目录归类。
- 截帧时间：无线耳机 13 秒、无线耳机 2 为 10 秒、耳机 UGC 为 13 秒；其他新增作品为 3 秒。
- 本地原视频未转码、未重命名、未删除，也不会被导入构建。部分文件是 HEVC，已安装浏览器的实际解码能力决定本地能否播放；上线 ImageKit 地址应优先提供 H.264/AAC MP4。

## 今后的封面选择

新增或替换封面使用 `npm run covers` 启动[本地封面工作流](./本地封面工作流.md)。先由用户选帧、调整构图并明确确认导出，再单独确认关联作品。不要自动采用第一帧、随机帧或未经确认的画面。已确认的覆盖映射在 `src/data/project-cover-overrides.json`，无映射时继续使用原封面；原始封面文件保留。
