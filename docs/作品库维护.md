# 作品库维护

本手册维护作品数据与发布边界；界面操作见 [本地作品管理工作台](./本地封面工作台使用教程.md)，图片文件命名见 [作品标题与本地 MP4 命名规范](./作品标题与本地MP4命名规范.md)，播放器比例与海报另见 [播放器媒体维护](./播放器媒体维护.md)。

## 当前结构

本地作品库有 **17 部作品、18 条 MP4**，其中 ID 16「MEXC 会员权益」包含 A/B 双版本，ID 17「MEXC 不用等了」为单独作品。分类数量：商业广告 8、创意短片 3、海外产品广告 4、视觉实验 2。`works.html` 只显示四个分类 Tab，默认商业广告；不显示「全部」筛选 Tab。

| 数据 | 真值与用途 |
| --- | --- |
| `src/data/projects.js` | 原有 ID 01–15 的来源、奖项与资料，使用视频 URL 映射；合并新增作品与其他数据 |
| `src/data/auto-projects.json` | 工作台新增作品（目前 ID 16、17），包括主视频、`variants[]` 与各版本 URL |
| `src/data/project-title-overrides.json` | 所有作品的中英文**最终展示标题**；不要手改源片名来改网页标题 |
| `src/data/local-video-paths.json` | ID 01–15 开发模式下的当前英文文件名与本地 MP4 路径 |
| `src/data/legacy-imagekit-urls.json` | ID 01–15 的线上 ImageKit URL；工作台可修改、复制、记录历史 |
| `src/data/project-order.json` | `featured`：恰好八件精选及其顺序；`all`：完整作品顺序；互不锁定 |
| `src/data/project-cover-overrides.json` | 17 张 3:4 卡片封面的分类路径 |
| `src/data/project-video-metadata.json` | 主版本实际显示比例、播放器原比例海报路径与选帧时间 |

四种分类 ID：`commercial`、`short-film`、`social`、`visual`。文旅宣传片归入商业广告；类别基于内容类型，不凭作品名猜测。

## 新增、改名与封面

- 使用 `npm run covers` 操作；点击作品卡片打开全屏双栏工作区，左侧直接播放/拖动本地 MP4 并选帧，右侧编辑中英文名称、两种封面、A/B 版本、ImageKit 与精选。新增版本在右侧选择 MP4 并可先播放预览；历史十五部作品也支持新增视频版本，单独写入 `legacy-video-variants.json`，不迁移原主视频。新作品由工作台生成唯一 ID，加入相应分类和 `auto-projects.json`，不自动成为首页精选；不要手动把新条目硬编码进 `PROJECTS`。
- 每部作品对应一张 3:4 卡片；工作台新增作品可追加 `variants[]`，播放器仅在至少两个版本时显示切换。各版本独立保存本地 MP4、播放比例、原比例海报和 ImageKit URL。
- 修改**英文标题**时，工作台同步重命名项目内的 MP4、3:4 封面和每版播放器海报，并原子更新引用；单独修改中文不改变本地文件名。图片按四分类目录、英文作品名保存，公开素材不使用随机 ID 后缀。
- 更换卡片封面先选作品、导入并选帧、预览新旧、确认应用；只替换 3:4 图片，不覆盖此前独立选帧的播放器海报。旧封面与迁移前文件保留在 Git 忽略的 `.cover-studio/project-revisions/`，**不可当作缓存清理**。
- 奖项、原平台证据 `sourceUrl`、作品 ID 不随标题或封面变更；无证据时奖项留空。`caseStudy` 暂为 `null`，尚无单独案例详情页。

## 独立排序

`project-order.json` 的 `featured` 始终是八个现有 ID，支持拖拽排序、从候选池替换成员；手机首页每页四件，播放器导航顺序相同。`all` 独立排序，按四个类别筛选展示，不强制「全部作品前八张等于精选」。未登记的新作品自动追加。工作台默认显示首页八部精选及四个分类，不显示重复的「全部作品」筛选；直接按住封面拖动，松手**自动保存排序**到本地数据（成功后短暂显示撤销操作），不再有单独的排序按钮和底部保存条。星标点击后明确选择被替换的精选，立即保存，始终恰好八部。搜索跨全部作品，但搜索结果禁用拖拽。

## 本地预览与线上发布

本地 `npm run dev` 始终播放 `assets/videos/works/` 下的 MP4；这些文件被 Git 忽略、不进入 `npm run build`。正式构建读取 ImageKit HTTPS 视频 URL。原有 15 部作品在 `legacy-imagekit-urls.json` 中的线上地址不因本地改名而变更；原有与新增作品都可在统一作品面板**关联已经上传的** ImageKit MP4 地址。工作台无上传接口，且不会自动 Git 提交或部署；缺少线上 URL 的视频在正式页面显示待上传。自动化测试不得向 ImageKit 发起真实媒体请求。

### 当前作品定位与跨页面封面更新

编辑器的「网页查看当前作品」打开 `works.html?category=分类&project=作品ID`，本地作品库会定位对应卡片。封面/海报保存后通过本机 SSE 通知已打开的 `5174` 预览页更新对应图片，不打断正在播放的视频；线上依旧需要 Git 与 Netlify 发布。隔离回归：`npm run check:workbench-draft-focus`、`npm run check:workbench-preview-sync`。

### 封面历史与恢复

工作台 3:4 封面、播放器海报（按 A/B 版本）均提供「历史」入口。历史只读取 `.cover-studio/project-revisions/cover-history/<ID>/` 和 `poster-history/<ID>/` 中真实存在、经过路径/格式校验的 WebP。恢复先备份当前图再替换旧图，保留原视频、其他版本及 ImageKit 配置。可从历史中再次恢复刚才的图片。隔离验证：`npm run check:workbench-history`。


### 末帧选取、即时刷新与保留上限

选帧区的「最后一帧」会解码视频实际末帧，避免因音频晚于画面结束而截帧错误。两种封面仍独立；本地保存后同时刷新工作台卡片、右侧预览和播放器 poster。保存期间不能关闭。历史最多 3 张 / 卡片或 3 张 / 该视频版本的海报，最旧图片和 JSON 一并自动清理。验证：`npm run check:workbench-endframe`。


### 详情全局导航及精确逐帧

工作台详情箭头统一依赖 `src/data/project-order.json` 的 `all` 顺序，可跨四个分类连续浏览 17 部作品；顶部只有作品身份、全局导航和关闭。网页定位入口在右侧「发布与预览」中，避免顶部按钮过密。`/api/import-project-video` 仅初始化会话和候选时间；不再执行 12 张缩略图生成；改用「首帧／上一帧／下一帧／尾帧」先快速 seek 本地视频，停止后仅请求最新一帧 FFmpeg，保留一个保存按钮。服务端会校验会话身份、项目绑定和索引，不允许任意路径访问；原视频不重编码。检查：`npm run check:workbench-navigation`、`npm run check:workbench-precision-frames` 和 `npm run check:workbench-fast-jog`。
