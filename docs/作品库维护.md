# 作品库维护

本手册维护作品数据与发布边界；界面操作见 [本地作品管理工作台](./本地封面工作台使用教程.md)，图片文件命名见 下文「作品标题与素材命名」，播放器比例与海报另见 [播放器媒体维护](./播放器媒体维护.md)。

## 当前结构

本地作品库有 **18 部作品、21 条 MP4**。多版本作品共用一张作品卡；ID 16、18、19 各包含两个视频版本。分类数量：商业广告 9、创意短片 3、海外产品广告 4、视觉实验 2。`works.html` 只显示四个分类 Tab，默认商业广告；不显示「全部」筛选 Tab。

| 数据 | 真值与用途 |
| --- | --- |
| `src/data/projects.js` | 原有 14 部作品的来源、奖项与资料，使用视频 URL 映射；合并新增作品与其他数据 |
| `src/data/auto-projects.json` | 工作台新增作品（目前 ID 16–19），包括主视频、`variants[]` 与各版本 URL |
| `src/data/project-title-overrides.json` | 所有作品的中英文**最终展示标题**；不要手改源片名来改网页标题 |
| `src/data/local-video-paths.json` | 原始作品开发模式下的当前英文文件名与本地 MP4 路径 |
| `src/data/legacy-imagekit-urls.json` | 原始作品的线上 ImageKit URL；工作台可修改、复制、记录历史 |
| `src/data/project-order.json` | `featured`：恰好八件精选及其顺序；`all`：完整作品顺序；互不锁定 |
| `src/data/project-cover-overrides.json` | 18 张 3:4 卡片封面的分类路径 |
| `src/data/project-video-metadata.json` | 主版本实际显示比例、播放器原比例海报路径与选帧时间 |
| `src/data/legacy-main-version-labels.json` | 原始作品主视频自定义的中英文版本名称 |

四种分类 ID：`commercial`、`short-film`、`social`、`visual`。文旅宣传片归入商业广告；类别基于内容类型，不凭作品名猜测。

## 新增、改名与封面

- 使用 `npm run covers` 操作；点击作品卡片打开全屏双栏工作区，左侧直接播放/拖动本地 MP4 并选帧，右侧通过「作品管理／封面与海报」两个互斥任务区管理版本、封面、共享标题、ImageKit 与精选；版本、共享名称和发布地址统一放在作品管理内。右侧「视频版本」任务区的标签单击切换视频，铅笔或「重命名当前版本」单击编辑中英文标签，**不依赖双击**；版本名称与切换按钮、当前版本标题同步，作品卡片标题保持独立。添加入口只在右侧「视频版本」区。原始作品新增的视频版本与主视频名称分别记录于 `legacy-video-variants.json`、`legacy-main-version-labels.json`，不迁移原主视频。新作品由工作台生成唯一 ID，加入相应分类和 `auto-projects.json`，不自动成为首页精选；不要手动把新条目硬编码进 `PROJECTS`。
- 每部作品对应一张 3:4 卡片；工作台新增作品可追加 `variants[]`，播放器仅在至少两个版本时显示切换。各版本独立保存本地 MP4、播放比例、原比例海报和 ImageKit URL。
- **视频版本顺序**单独记在 `src/data/project-version-order.json`：拖动视频版本标签松手自动保存，网页播放器使用第一个作为默认版本。`main` 仍是固定主版本身份，重新排序不会改变封面、海报、媒体路径或线上视频 URL。
- 修改**英文标题**时，工作台同步重命名项目内的 MP4、3:4 封面和每版播放器海报，并原子更新引用；单独修改中文不改变本地文件名。图片按四分类目录、英文作品名保存，公开素材不使用随机 ID 后缀。
- 更换卡片封面：选作品 → 播放器时间轴定位或导入图片 → 查看预览 → 单击「保存」即可完成取帧与替换；只替换 3:4 图片，不覆盖此前独立选帧的播放器海报。旧封面与迁移前文件保留在 Git 忽略的 `.cover-studio/project-revisions/`，**不可当作缓存清理**。
- 奖项、原平台证据 `sourceUrl`、作品 ID 不随标题或封面变更；无证据时奖项留空。`caseStudy` 暂为 `null`，尚无单独案例详情页。

### 命名、路径和更名边界

- **中文**：采用“品牌／主体＋作品类型”或原创片名；汉字词组间不乱加空格，英文品牌与中文之间、中文品牌与版本号之间各留一个半角空格，例如“MEXC 会员权益”“通义万相 2.2 宣传片”。
- **英文**：主要单词 Title Case，但优先遵守 CHAGEE、MEXC、Wan2.2 等注册名称；只用单个半角空格，描述真实内容而不是逐字硬译。常用 `Brand Commercial`（品牌片）、`Comedy Ad`（喜剧广告）、`Demo`（体验展示）；多版本在英文文件名后用 ` - Version A`／` - Version B`。
- **本地 MP4**：位于 `assets/videos/works/<分类目录>/<英文标题>.mp4`。旧作品路径看 `src/data/local-video-paths.json`，原始旧路径由 `local-video-origins.json` 记录；新增作品及版本以 `auto-projects.json` 或 `legacy-video-variants.json` 内的路径为准。作品 16 的两个视频为 `MEXC Member Perks - Version A.mp4` 与 `MEXC Member Perks - Version B.mp4`。
- **正式卡片封面**：`assets/images/project-covers/<category>/<English Title>.webp`，比例 3:4；**播放器海报**：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`，保持原视频显示比例（包括 SAR）。`category` 仅为 `commercial`、`short-film`、`social`、`visual`；各视频版本拥有独立海报。更换一种封面不能覆盖另一种。
- **编辑与回滚**：在作品库单击名称或在详情页编辑中英文输入框。英文标题保存时，`/api/update-title` 同步重命名**项目内** MP4、卡片封面、每版海报及 JSON 路径映射，失败时回滚；仅改中文不更改媒体文件名。修改及旧图保存在 `.cover-studio/project-revisions/`，含 `title-<ID>-<UUID>.json`、`title-style-20261107-backup.json` 与 `media-catalog-20261107/`；历史不是缓存，不能清理。
- **禁止联动**：更名不改变已上传的 ImageKit HTTPS URL、外部原片目录、视频内容、作品 ID、奖项或精选排序；不要仅凭中文标题拼接 MP4 路径。图片导入与恢复须校验实际比例，保留源画面，禁止横向拉伸。
- **检查**：修改标题或文件名后运行 `npm run check:asset-catalog`、`npm run check:english-copy`、`npm run check:overseas-names`、`node scripts/check-cover-studio-title-mp4.mjs`、`node scripts/check-cover-studio-inline-bilingual.mjs`，同时运行构建与精选排序检查。

## 独立排序

`project-order.json` 的 `featured` 始终是八个现有 ID，支持拖拽排序、从候选池替换成员；手机首页每页四件，播放器导航顺序相同。`all` 独立排序，按四个类别筛选展示，不强制「全部作品前八张等于精选」。未登记的新作品自动追加。工作台默认显示首页八部精选及四个分类，不显示重复的「全部作品」筛选；直接按住封面拖动，松手**自动保存排序**到本地数据（成功后短暂显示撤销操作），不再有单独的排序按钮和底部保存条。星标点击后明确选择被替换的精选，立即保存，始终恰好八部。搜索跨全部作品，但搜索结果禁用拖拽。

## 本地预览与线上发布

本地 `npm run dev` 始终播放 `assets/videos/works/` 下的 MP4；这些文件被 Git 忽略、不进入 `npm run build`。正式构建读取 ImageKit HTTPS 视频 URL。原始作品在 `legacy-imagekit-urls.json` 中的主版本线上地址不因本地改名而变更；原有与新增作品的各版本都可在工作台**关联已经上传的** ImageKit MP4 地址。编辑器固定 `https://ik.imagekit.io/Ailuren/tr:orig-true/videos/` 前缀，只修改后缀并显式保存。工作台无上传接口，不会自动 Git 提交或部署；缺少线上 URL 的视频在正式页面显示待上传。自动化测试不得向 ImageKit 发起真实媒体请求。

### 当前作品定位与跨页面封面更新

编辑器的「网页查看当前作品」打开 `works.html?category=分类&project=作品ID`，本地作品库会定位对应卡片。封面/海报保存后通过本机 SSE 通知已打开的 `5174` 预览页更新对应图片，不打断正在播放的视频；线上依旧需要 Git 与 Netlify 发布。隔离回归：`npm run check:workbench-draft-focus`、`npm run check:workbench-preview-sync`。

### 封面历史与恢复

工作台 3:4 封面、播放器海报（按 A/B 版本）均提供「历史」入口。历史只读取 `.cover-studio/project-revisions/cover-history/<ID>/` 和 `poster-history/<ID>/` 中真实存在、经过路径/格式校验的 WebP。恢复先备份当前图再替换旧图，保留原视频、其他版本及 ImageKit 配置。可从历史中再次恢复刚才的图片。隔离验证：`npm run check:workbench-history`。


### 末帧选取、即时刷新与保留上限

选帧区的「最后一帧」会解码视频实际末帧，避免因音频晚于画面结束而截帧错误。两种封面仍独立；本地保存后同时刷新工作台卡片、右侧预览和播放器 poster。保存期间不能关闭。历史最多 3 张 / 卡片或 3 张 / 该视频版本的海报，最旧图片和 JSON 一并自动清理。验证：`npm run check:workbench-endframe`。


### 详情全局导航及精确逐帧

工作台详情箭头统一依赖 `src/data/project-order.json` 的 `all` 顺序，可跨四个分类连续浏览 18 部作品；顶部只有作品身份、全局导航和关闭。新增视频版本的入口在右侧「视频版本」区；网页定位入口在右侧「发布与预览」中。`/api/import-project-video` 仅初始化会话和候选时间；不再执行 12 张缩略图生成；改用「首帧／上一帧／下一帧／尾帧」先快速 seek 本地视频，停止后仅请求最新一帧 FFmpeg，保留一个保存按钮。服务端会校验会话身份、项目绑定和索引，不允许任意路径访问；原视频不重编码。检查：`npm run check:workbench-navigation`、`npm run check:workbench-precision-frames` 和 `npm run check:workbench-fast-jog`。
