# 作品库维护

本手册维护作品数据与发布边界；界面操作见 [作品管理工作台](./作品管理工作台使用指南.md)，图片文件命名见 下文「作品标题与素材命名」，播放器比例与海报另见 [播放器媒体维护](./播放器媒体维护.md)。

## 当前结构

本地作品库有 **19 部作品、23 条 MP4**。多版本作品共用一张作品卡；ID 16、18 各包含两个视频版本，ID 19 包含三个。分类数量：商业广告 9、创意短片 4、海外产品广告 4、视觉实验 2。`works.html` 只显示四个分类 Tab，默认商业广告；不显示「全部」筛选 Tab。

12 份 JSON 的完整字段权威表、读取顺序及工作台写入责任统一见本文件末尾的「作品数据模型与读写契约」。

四种分类 ID：`commercial`、`short-film`、`social`、`visual`。作品卡可选 `typeLabel` 中英文子类型（如 ID 20「AI 漫剧 / AI Short Drama」），不新增第五个分类。文旅宣传片归入商业广告；类别基于内容类型，不凭作品名猜测。

## 新增、改名与封面

- 使用 `npm run workbench` 操作；点击作品卡片打开全屏双栏工作区，左侧直接播放/拖动本地 MP4 并选帧，右侧通过「作品管理／封面与海报」两个互斥任务区管理版本、封面、共享标题、ImageKit 与精选；版本、共享名称和发布地址统一放在作品管理内。右侧「作品统一名称」在最上方，全部 A/B/C 视频共用；下方视频标签单击切换，所选版本的中英文名称输入框默认展开，修改时才显示保存和撤销；**无需铅笔、额外重命名按钮或双击**。视频版次可拖拽排序，同行最右单个垃圾桶仅归档当前视频，底部「整部移入回收站」则归档全作品。原始作品新增的视频版本与主视频名称分别记录于 `legacy-video-variants.json`、`legacy-main-version-labels.json`，不迁移原主视频。新作品由工作台生成唯一 ID，加入相应分类和 `auto-projects.json`，不自动成为首页精选；不要手动把新条目硬编码进 `PROJECTS`。
- 每部作品对应一张 3:4 卡片；工作台新增作品可追加 `variants[]`，播放器仅在至少两个版本时显示切换。各版本独立保存本地 MP4、播放比例、原比例海报和 ImageKit URL。
- **视频版本顺序**单独记在 `src/data/project-version-order.json`：拖动视频版本标签松手自动保存，网页播放器使用第一个作为默认版本。`main` 仍是固定主版本身份，重新排序不会改变封面、海报、媒体路径或线上视频 URL。
- 修改**英文标题**时，工作台同步重命名项目内的 MP4、3:4 封面和每版播放器海报，并原子更新引用；单独修改中文不改变本地文件名。图片按四分类目录、英文作品名保存，公开素材不使用随机 ID 后缀。
- 更换卡片封面：选作品 → 播放器时间轴定位或导入图片 → 查看预览 → 单击「保存」即可完成取帧与替换；只替换 3:4 图片，不覆盖此前独立选帧的播放器海报。旧封面与迁移前文件保留在 Git 忽略的 `.cover-studio/project-revisions/`，**不可当作缓存清理**。
- 奖项、原平台证据 `sourceUrl`、作品 ID 不随标题或封面变更；无证据时奖项留空。`caseStudy` 暂为 `null`，尚无单独案例详情页。

### 命名、路径和更名边界

- **中文**：采用“品牌／主体＋作品类型”或原创片名；汉字词组间不乱加空格，英文品牌与中文之间、中文品牌与版本号之间各留一个半角空格，例如“MEXC 会员权益”“通义万相 2.2 宣传片”。
- **英文**：主要单词 Title Case，但优先遵守 CHAGEE、MEXC、Wan2.2 等注册名称；只用单个半角空格，描述真实内容而不是逐字硬译。常用 `Brand Commercial`（品牌片）、`Comedy Ad`（喜剧广告）、`Demo`（体验展示）；多版本在英文文件名后用 ` - Version A`／` - Version B`。
- **本地 MP4**：位于 `assets/videos/works/<分类目录>/<英文标题>.mp4`。旧作品路径看 `src/data/local-video-paths.json`，原始旧路径由 `local-video-origins.json` 记录；新增作品及版本以 `auto-projects.json` 或 `legacy-video-variants.json` 内的路径为准。作品 16 的两个视频为 `MEXC Member Perks - Version A.mp4` 与 `MEXC Member Perks - Version B.mp4`。
- **正式卡片封面**：`assets/images/project-covers/<category>/<English Title>.webp`，比例 3:4；**播放器海报**：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`，保持原视频显示比例（包括 SAR）。`category` 仅为 `commercial`、`short-film`、`social`、`visual`；各视频版本拥有独立海报。更换一种封面不能覆盖另一种。
- **编辑与回滚**：在作品库单击名称或在详情页编辑中英文输入框。英文标题保存时，`/api/update-title` 同步重命名**项目内** MP4、卡片封面、每版海报及 JSON 路径映射，失败时回滚；仅改中文不更改媒体文件名。修改及旧图保存在 `.cover-studio/project-revisions/`，含 `title-<ID>-<UUID>.json`、`title-style-20261107-backup.json` 与 `media-catalog-20261107/`；历史不是缓存，不能清理。
- **禁止联动**：更名不改变已上传的 ImageKit HTTPS URL、外部原片目录、视频内容、作品 ID、奖项或精选排序；不要仅凭中文标题拼接 MP4 路径。图片导入与恢复须校验实际比例，保留源画面，禁止横向拉伸。
- **检查**：修改标题或文件名后运行 `npm run check:asset-catalog`、`npm run check:english-copy`、`npm run check:overseas-names`、`node scripts/checks/workbench/check-cover-studio-title-mp4.mjs`、`node scripts/checks/workbench/check-cover-studio-inline-bilingual.mjs`，同时运行构建与精选排序检查。

## 独立排序

`project-order.json` 的 `featured` 始终是八个现有 ID，支持拖拽排序、从候选池替换成员；手机首页连续展示八件（四排两列，不分页），播放器导航顺序与精选一致。`all` 独立排序，按四个类别筛选展示，不强制「全部作品前八张等于精选」。未登记的新作品自动追加。工作台默认显示首页八部精选及四个分类，不显示重复的「全部作品」筛选；直接按住封面拖动，松手**自动保存排序**到本地数据（成功后短暂显示撤销操作），不再有单独的排序按钮和底部保存条。星标点击后明确选择被替换的精选，立即保存，始终恰好八部。搜索跨全部作品，但搜索结果禁用拖拽。

## 本地预览与线上发布

公开 README 只展示已有作品与真实证明：招聘测试或独立创作 Demo 必须如实标明其性质，未经依据不得将其描述为品牌正式委托／官方广告。公开封面引用必须使用已存在的仓库路径，不能依赖本机私有视频或未提交的临时海报。

本地 `npm run dev` 始终播放 `assets/videos/works/` 下的 MP4；这些文件被 Git 忽略、不进入 `npm run build`。正式构建读取 ImageKit HTTPS 视频 URL。原始作品在 `legacy-imagekit-urls.json` 中的主版本线上地址不因本地改名而变更；原有与新增作品的各版本都可在工作台**关联已经上传的** ImageKit MP4 地址。编辑器固定 `https://ik.imagekit.io/Ailuren/tr:orig-true/videos/` 前缀，只修改后缀并显式保存。工作台无上传接口，不会自动 Git 提交或部署；缺少线上 URL 的视频在正式页面显示待上传。自动化测试不得向 ImageKit 发起真实媒体请求。

### 当前作品定位与跨页面封面更新

编辑器的「网页查看当前作品」使用 `works.html?category=分类&project=作品ID`：定位并短暂高亮对应卡片，随后移除 `project` 参数，**不自动打开播放器**。公开分享使用独立的 `works.html?watch=作品ID`：切到对应分类，准备海报后打开播放器（**不自动播放**），关闭／Back 恢复作品库卡片、Forward 重开。播放器已移除「复制作品链接」按钮，`?watch` 直达地址仍可通过浏览器地址栏访问；公开 `?watch` 不会覆盖工作台 `?project` 的含义。当前静态 OG 元信息仍是作品库通用图，不宣称逐作品有专属分享预览。封面/海报保存后通过本机 SSE 通知已打开的 `5174` 预览页更新对应图片，不打断正在播放的视频；线上依旧需要 Git 与 Netlify 发布。隔离回归：`npm run check:workbench-draft-focus`、`npm run check:workbench-preview-sync`。

### 封面历史与恢复

工作台 3:4 封面、播放器海报（按 A/B 版本）均提供「历史」入口。历史只读取 `.cover-studio/project-revisions/cover-history/<ID>/` 和 `poster-history/<ID>/` 中真实存在、经过路径/格式校验的 WebP。恢复先备份当前图再替换旧图，保留原视频、其他版本及 ImageKit 配置。可从历史中再次恢复刚才的图片。隔离验证：`npm run check:workbench-history`。


### 末帧选取、即时刷新与保留上限

选帧区的「最后一帧」会解码视频实际末帧，避免因音频晚于画面结束而截帧错误。两种封面仍独立；本地保存后同时刷新工作台卡片、右侧预览和播放器 poster。保存期间不能关闭。历史最多 3 张 / 卡片或 3 张 / 该视频版本的海报，最旧图片和 JSON 一并自动清理。验证：`npm run check:workbench-endframe`。


### 详情全局导航及精确逐帧

工作台详情箭头统一依赖 `src/data/project-order.json` 的 `all` 顺序，可跨四个分类按当前可见作品数量连续浏览；顶部只有作品身份、全局导航和关闭。新增视频版本的入口在右侧「视频版本」区；网页定位入口在右侧「发布与预览」中。`/api/import-project-video` 仅初始化会话和候选时间；不再执行 12 张缩略图生成；改用「首帧／上一帧／下一帧／尾帧」先快速 seek 本地视频，停止后仅请求最新一帧 FFmpeg，保留一个保存按钮。服务端会校验会话身份、项目绑定和索引，不允许任意路径访问；原视频不重编码。检查：`npm run check:workbench-navigation`、`npm run check:workbench-precision-frames` 和 `npm run check:workbench-fast-jog`。


## 作品数据模型与读写契约

### 一句话模型

- **`Project`**：一部作品只有一个稳定 `id`、一个分类和一张 **3:4 作品卡封面**，但可包含多条视频。
- **`VideoVersion`**：每条视频有独立的 `id`、`videoUrl`、`playerPoster`、显示宽高与时长。固定的 `main` 是版本身份，**不是**永远首播的版本。
- **展示清单不是单份 JSON**：`src/data/projects.js` 综合原始作品、工作台新增作品及覆盖索引后输出 `PROJECTS` 和 `FEATURED_PROJECTS`。不要直接编辑最终导出值。
- **两类持久化**：Git 可跟踪的 `src/data/*.json`／封面文件决定下次网站构建内容；Git 忽略的 `.cover-studio/` 保存本地导入会话、历史与恢复证据。工作台写入不会自动推送 GitHub、上传 ImageKit 或部署网页。

### 当前 12 份 JSON 文件的职责

以下路径均以 `src/data/` 为基准。公开运行时直接导入其中 11 份（全部除了 `local-video-origins.json`），但工作台可能读取或写入全部 12 份。

| 文件 | 内容及权威范围 | 主要读写位置 |
| --- | --- | --- |
| `auto-projects.json` | 工作台新增作品的基本信息、主版本的本地/线上视频、封面相对路径，以及新增作品的 `variants[]` | `projects.js` 读取；`project-publisher.mjs` 创建；`project-versions.mjs` 增版/URL/标签；`project-titles.mjs` 更名 |
| `legacy-imagekit-urls.json` | 原有作品 **main** 视频的正式 ImageKit 地址，不通过本地 MP4 路径推导 | `projects.js` 读取；`project-versions.mjs` 关联 URL |
| `legacy-video-variants.json` | 原有作品新增的非 main 视频列表与各版本媒体/海报 | `projects.js` 读取；`project-versions.mjs`、`project-poster.mjs` 修改 |
| `legacy-main-version-labels.json` | 原有作品主版本自定义中英文标签；当前允许为空对象 | `projects.js` 读取；`project-versions.mjs` 更新 |
| `local-video-paths.json` | 原有作品在 **Vite 开发环境**使用的当前 MP4 相对路径（英文命名后的文件） | `projects.js` 开发路径读取；`project-titles.mjs` 维护 |
| `local-video-origins.json` | 旧原片路径/文件名的历史来源记录；**不参与公开运行时的 `projects.js` 合并** | `project-titles.mjs` 更名过程读取，禁止当缓存清理 |
| `project-cover-overrides.json` | 已有作品的 3:4 卡片封面覆盖路径，优先于基础作品封面；新增作品通常也有 `coverFile` | `projects.js`、`vite.config.js` 读取；工作台封面保存/更名写入 |
| `project-title-overrides.json` | **最终展示标题**的中英文覆盖；优先于 `BASE_PROJECTS` 和 `auto-projects.json` 的 `title` | `projects.js` 读取；`project-titles.mjs` 更名写入 |
| `project-video-metadata.json` | 主版本显示宽高/时长、原比例播放器海报、选帧元数据 | `projects.js` 读取；`project-publisher.mjs` 新增；`project-poster.mjs` 维护 |
| `project-order.json` | `featured`：恰好 **8 个不同且有效的 ID**；`all`：整库展示顺序，独立于 `featured` | `projects.js`、`vite.config.js` 读取；`project-order.mjs` 保存 |
| `project-version-order.json` | 每部作品的版本 ID 排列；只改变展示顺序，**不改变 `main` 的身份** | `projects.js` 读取；`version-order.js` 排序；`project-version-order.mjs` 保存 |
| `archive-state.json` | `works` / `versions` 可恢复的隐藏标记，不删除 MP4 或图片；归档 main 时可保留其它版本 | `projects.js` 过滤；`project-archive.mjs` 归档/恢复 |

注意：`legacy-video-variants.json`、`legacy-main-version-labels.json` 即使现在是空对象，也分别对应仍在使用的工作台能力，**不能仅因内容为空判定为冗余**。

### 实际读取顺序与最终覆盖关系

```text
BASE_PROJECTS（projects.js 内原有作品） + auto-projects.json（新增作品）
  → 补全视频版本：
       auto 项目用自带 variants[]
       原有项目用 legacy-video-variants.json
  → 应用 archive-state.json 的版本隐藏与 mainVersionArchived
  → 应用 project-version-order.json 的版本顺序
  → 应用 project-title-overrides.json 的最终标题
  → 应用 project-cover-overrides.json 的卡片封面
  → 应用 project-video-metadata.json 的主版本比例、时长与海报
  → 按 archive-state.json.works 隐藏整部作品
  → 按 project-order.json.all 排序为 PROJECTS
  → 按 project-order.json.featured 精确映射为 FEATURED_PROJECTS
```

严格说，上述是**逻辑概览**：`projects.js` 在同一映射阶段展开覆盖字段；不要假定每一行是独立的运行时事务。细节以 [源码](../src/data/projects.js) 为准。

| 字段 / 行为 | 最终优先来源 | 易踩坑 |
| --- | --- | --- |
| `id` / `category` / 奖项 / 来源链接 | 初始作品或新增作品条目 | ID 长期稳定，不能靠当前排序下标重新编号 |
| `title.{zh,en}` | `project-title-overrides.json[id]`，不存在时使用初始条目 | 改中文标题不应重命名 MP4；更改英文标题走工作台带历史的事务 |
| `cover` | `project-cover-overrides.json[id]`；否则新增条目的 `coverFile` | 作品卡 3:4，**不是**播放器海报 |
| 主 `videoUrl` | 原有项目：`legacy-imagekit-urls.json`；新增项目：`auto-projects.json` | `import.meta.env.DEV` 下改为本地 MP4；生产使用登记的 HTTPS URL，缺失则 `null` |
| 非主版本 `variants[]` | 新项目自带数组；原有项目 `legacy-video-variants.json[id]` | 每版自己的海报、URL、标签，不复用主版的比例 |
| 主版本标签 | 新项目 `mainVersionLabel` 或旧项目 `legacy-main-version-labels[id]` | `main` 固定身份，可因排序不在第一位 |
| 版本默认选中 | `projectVideoVersions(project)[0]` | `project-version-order.json` 可让 B/C 成为第一可见版；归档的 main 可能不可见 |
| `featured` / 精选顺序 | `project-order.json.featured` | 旧 `BASE_PROJECTS` 仍存 `featured: true/false`，**不是最终真值** |
| 全部作品顺序 | `project-order.json.all` | 未在列表中的新增作品追加；不强制精选等于「全部」前八件 |
| 隐藏状态 | `archive-state.json` | 只隐藏，不丢弃原文件及索引；恢复还要满足版本约束 |

### 作品管理工作台：操作 → 写入责任

| 用户操作 | 服务端入口 / 核心处理 | 可能更新的持久化位置 |
| --- | --- | --- |
| 新增作品 | `/api/create-project` → `project-publisher.mjs` | `auto-projects.json`、`project-video-metadata.json`、本地 MP4、3:4 封面、播放器海报，`.cover-studio/project-revisions/` |
| 作品统一更名 | `/api/update-title` → `project-titles.mjs` | 标题覆盖、本地路径、原始路径记录、新作品条目、封面覆盖、视频元数据及对应文件名；带恢复记录 |
| 修改精选/全部作品排序 | `/api/save-order` → `project-order.mjs` | 仅 `project-order.json` 和排序历史 |
| 视频版本新增/标签/线上关联 | `/api/add-version`、`/api/update-version-label`、`/api/bind-imagekit` → `project-versions.mjs` | 原有/新增版本的 JSON、必要的本地媒体和修订历史；**不执行 ImageKit 上传** |
| 视频版本拖拽排序 | `/api/save-version-order` → `project-version-order.mjs` | 仅 `project-version-order.json` 和排序历史 |
| 更换/恢复图片 | `/api/associate`、`/api/associate-poster`、`/api/restore-artwork` → 图片与历史模块 | 3:4 封面或某条视频独立海报、对应路径/元数据和恢复历史 |
| 归档/恢复 | `/api/archive-item`、`/api/restore-item` → `project-archive.mjs` | `archive-state.json` 和归档历史；不物理删作品或视频 |

所有修改均为**本机磁盘行为**；工作台中显示的线上 URL 只是关联已上传资源，保存并不替你部署站点。具体交互与回滚步骤见 [作品管理工作台技术维护](./作品管理工作台技术维护.md)。

### 安全修改数据的最短流程

1. 先运行 `git status --short --branch`，确认本地草稿、改名中的文件及正在运行的工作台；不要用新服务操作真实 `.cover-studio/`。
2. 新增/更名/封面优先使用工作台 UI，必要时只在隔离副本做写入自动化；**不手工拼路径、不整体覆盖旧 JSON**。
3. 保存后对照 `src/data/projects.js` 的最终导出、`projectVideoVersions()` 的首播版本，并确认图片路径/本地 MP4 真正存在。
4. 运行 `npm run build`、`npm run check:asset-catalog`、`npm run check:curated-order`、`npm run check:work-media`、`git diff --check`；复杂写入走 [测试与回归维护](./测试与回归维护.md) 指定的工作台隔离回归。
5. 等 Git 提交和平台发布后线上才会更新；自动化检查不得触发真实 ImageKit 播放或缩略图费用。

**不在这里建立第二套 Project JSON Schema/写入器。** 本字典是现有代码的导航与契约说明；若未来需要机器可验证 Schema，应从工作台真实写入结构提取，并由双方共享，而不是维护另一份易漂移的手写真值。
