# 本地工作台技术维护

面向维护者。操作步骤集中在 [本地封面工作台使用教程](./本地封面工作台使用教程.md)，这里仅说明数据、接口、依赖和验证，避免两份文档重复记录按钮操作。

## 进程与媒体边界

- `npm run covers` 启动 `tools/cover-studio/server.mjs`，仅监听 `127.0.0.1:5190`；要求本机 `ffmpeg`、`ffprobe`。工作台不参与 Vite 生产构建。
- 默认 MP4 目录 `/Users/ailuren/Desktop/重要资料/个人网页作品集-imagekit本地`，可用 `COVER_STUDIO_VIDEO_DIR` 覆盖作隔离测试；仅列目录内 MP4，不遍历子目录。导入文件首次写入 `.cover-studio/sessions/<ID>/`，然后由 SHA-256 内容寻址存储进行**同内容去重**；每个会话继续保留 `source.mp4` 路径，通过只读硬链接共享数据，不修改外部原片或正式作品 MP4。
- 当前统一编辑器通过本地 MP4 播放器时间轴与首帧／上一帧／下一帧／尾帧定位，不生成 12 张候选缩略图；必要时导入自定义 JPG/PNG/WebP。3:4 封面由本机 FFmpeg 编码为 900×1200 WebP，完整保留画面并以模糊背景补边；原比例播放器海报按源视频真实显示比例（含 SAR）独立生成。只保存当前选中的封面类型，不覆盖另一种封面。
- 临时导出记录保存在 `.cover-studio/exports/`，封面关联和作品操作记录保存在 `.cover-studio/` 和 `.cover-studio/project-revisions/`。该目录被 Git 忽略，含用户可能需要回溯的素材，**不自动删除**。

## 本地会话视频去重与恢复（第二阶段）

- `npm run covers:storage:scan`：只读扫描会话的独立视频数、重复字节与预览图占用；`npm run covers:storage:dedupe`：将具有相同 SHA-256 的会话 `source.mp4` 原子替换为同一个**只读硬链接**，不修改 `session.json`、会话 ID、导出引用和视频内容。新导入的视频也自动复用这一存储。共享对象位于 Git 忽略的 `.cover-studio/source-objects/`。
- `npm run covers:storage:verify`：重新计算全部共享对象与会话视频的哈希，确认对象完整且会话链接可读；`npm run covers:storage:restore -- <会话 UUID>`：为指定会话恢复可单独编辑的 MP4 独立副本，不影响其他会话。检查脚本为 `npm run check:workbench-storage`。
- **只读保护**：共享对象与会话视频不可原位修改，导出新增作品／版本时仍生成正式目录下的**独立 MP4**，不硬链接到正式目录。若需要修改源视频，应从外部原始素材重新导入。
- **不清理历史**：`.cover-studio/project-revisions/` 的封面、海报及名称恢复记录不属于缓存；`sessions/` 下的选帧 PNG、旧候选 JPG、未确认导出以及 `exports/` 均保留。尚未启用自动按年龄删除会话，避免误删未完成的草稿或旧选帧。
- 现有工作台若在改动前就已启动，其 Node 进程需**下次手动重启**后才能自动复用新导入视频；已完成的离线去重不需要重启，原路径保持可用。

## ImageKit 与发布

工作台仅允许用户点击保存后绑定**已上传**的 ImageKit MP4 URL；上传按钮及服务器上传接口已移除。地址前缀为 `https://ik.imagekit.io/Ailuren/tr:orig-true/videos/`，每个版本单独绑定。**ImageKit URL 关联 ≠ Git 提交 ≠ Netlify 部署**。版本名称通过仅监听本机 `127.0.0.1:5190` 的 `POST /api/update-version-label` 保存至对应 JSON 与 `.cover-studio/project-revisions/` 历史，不连接生产网页或 ImageKit。

生产构建不携带 `assets/videos/works/` 的本地原片。开发模式下本机视频优先且不自动回退 ImageKit；自动化测试必须使用 `scripts/lib/safe-media.mjs` 的受保护浏览器环境，零真实 CDN 视频请求。

## 封面替换安全边界

所有作品（包括 8 件精选）均允许通过工作台更换封面。日常在统一编辑工作区选帧后一次保存；旧式高级测试流程仍可先核对并勾选确认后调用 `/api/associate`。服务端校验导出 ID、作品 ID、旧映射并备份原封面；正式文件名不附加随机 ID，不修改视频、播放器海报、精选成员或排序。

命名、分类路径和文件更名回滚规则统一见 [作品标题与素材命名](./作品库维护.md#作品标题与素材命名当前-18-部)。

## 统一作品库与宽屏编辑工作区（默认入口）

日常工作台直接展示 8 部首页精选及四种分类，不使用「全部作品」重复筛选；中英文搜索可覆盖整个作品库。作品卡片本身可按住拖动，松手自动保存顺序并提供撤销，仍通过服务端的期待旧值校验和修订记录保证安全。

点击作品封面打开全屏编辑工作区（`tools/cover-studio/library-ui.js`）：顶部固定作品身份和关闭按钮，桌面左侧展示视频与选帧、右侧展示名称、两种封面、版本、ImageKit 和精选状态。1440×900 的常用操作无需跳转页面或纵向滚动整个弹层；较矮桌面窗口仅保留必要的局部滚动；窄屏（≤920px）只展示 Mac 桌面使用提示。

- `GET /project-video/:projectId/:variantId` 使用 `currentVideo` 检查分类路径、实际文件和版本后，按 HTTP Range 返回本机 MP4；使用 `tools/cover-studio/library-player.js` 控制播放、暂停、时间轴、精确时间和本地视频封面。没有 ImageKit 媒体请求，也不为预览重新编码。
- `tools/cover-studio/library-cover-editor.js` 在左侧提供「首帧、上一帧、下一帧、尾帧」和导入自定义图片，不再生成 12 张采样缩略图；拖动时间轴或逐帧按键先立即 seek 本地视频，停止约 260ms 后才通过 `/api/frame` 取最新精确 PNG；保存前校验最终画面，避免 FFmpeg 阻塞逐帧操作。
- 删除用户可见的「完整画面／填满 3:4」双按钮。**3:4 默认始终完整保留取帧图像，使用柔和模糊背景填空白边缘**；原比例播放器海报始终按原视频显示比例保存，图像比例不符会阻止保存。
- 选中帧时右侧被编辑的封面直接预览新图；3:4 预览通过 `blob:` 临时对象地址满足 CSP 的 `img-src 'self' blob:` 约束，关闭或换版本时恢复旧图并撤销临时对象。点击一次保存后调用既有 `/api/export`＋`/api/associate` 或 `/api/associate-poster`，严格隔离封面类型及版本、备份旧图。
- 右侧「视频版本」区的「添加视频版本」适用于新作品和原有作品：选择 MP4 后先通过浏览器临时 `blob:` URL 在左侧播放器预览，再通过 `/api/import?kind=video&candidates=0` 和 `/api/add-version` 增加独立版本；自动生成初始海报，之后可以单独选帧。原有作品的新增版本写入 `legacy-video-variants.json`，不会隐式迁移或覆盖主版本。隔离回归：`node scripts/check-cover-studio-legacy-version.mjs`。
- ImageKit 仅支持在同一面板按视频版本更新已上传的 HTTPS MP4 URL；历史地址在 `legacy-imagekit-urls.json`，新增在 `auto-projects.json`。保存本地 URL 不会上传媒体或触发 Netlify 部署。
- 旧式单独排序/导出/版本管理模块的代码目前保留供既有回归工具兼容，**已从用户日常工作台导航中隐藏**，不能再次引入重复入口。

端到端验收 `npm run check:workbench-full-flow` 在隔离临时项目验证 206 Range、播放、拖动时间轴、逐帧微调、未保存保护、固定关闭按钮、新版本 MP4 预览和创建、ImageKit 关联、桌面一屏布局及零修改正式文件。其他验证仍用 `check:workbench-ux`、`check:workbench-save`、`check:workbench-drag`。

## 工作台精确逐帧选取（替代 12 张均匀采样图）

日常编辑器的 `POST /api/import-project-video` 只初始化当前本地 MP4 会话，探测视频真实 `fps`、`duration` 和 `lastFrameTime`，**不再生成 12 张缩略图**。此前统一编辑器用的 `GET /api/candidate/:sessionId/:index` 已移除。旧的独立高级兼容工具仍保留其候选图逻辑供旧测试，日常工作台不会触发它。

- 播放器时间轴和「首帧／上一帧／下一帧／尾帧」四个按钮控制定位，视频时间标识显示毫秒；逐帧点击先立即操作本地 HTMLVideoElement，停止约 260ms 后只为最新位置请求 `POST /api/frame`，缓存中的旧请求用 token 校验忽略。逐帧按钮按真实 fps 换算为整数帧索引，避免连续加减浮点误差；可变帧率素材以平均 fps 近似定位，实际画面仍以 FFmpeg 解码为准。
- 开始选帧时保持旧封面，不自动选择第 0 秒的黑帧；唯一保存按钮在未选帧时自动取当前播放时间，已有选帧则保存指定画面；提交前不改磁盘。卡片 3:4 和播放器原比例海报独立备份。
- ImageKit URL 单击进入编辑状态：固定前缀 `https://ik.imagekit.io/Ailuren/tr:orig-true/videos/` 只读且可单独复制，输入框仅编辑文件名／路径后缀；粘贴同前缀完整地址时自动提取后缀，其他账户前缀会被拒绝。明确点击「保存」「取消」；Enter/Esc 可辅助操作，失焦不静默保存，切作品受草稿保护。
- 详情全局导航相对整个标题栏水平居中，统一行按钮等高、内容居中、不可折行，首帧/尾帧不预设高亮。详见 `docs/设计规范.md`。
- 回归运行 `npm run check:workbench-fast-jog`、`npm run check:workbench-precision-frames`、`npm run check:workbench-full-flow` 和 `npm run check:workbench-endframe`。所有有写入的测试在隔离副本运行，不访问 ImageKit。

## 桌面工作台与作品间导航

工作台只面向 Mac 桌面浏览器，窄屏（宽度 ≤920px）或纯触屏访问时显示电脑专用提示，不提供手机编辑模式。已移除 `tools/cover-studio/style.css` 内 33 组手机适配媒体查询、`library-ui.js` 的触摸长按拖拽逻辑和旧工作台手机交互测试；保留低高度笔记本窗口需要的紧凑样式。**公开网站**的手机布局和播放器交互不变。

详情顶部有「全部作品」和「上一部／下一部」与位置计数，始终按 `project-order.json.all` 的 **18 部全局顺序**，跨越精选、商业广告及其他分类 Tab。无论从哪个筛选或搜索进入都可以连续浏览所有作品；跨分类时自动更新底层作品库的分类，退出详情会聚焦当前作品，而非回到旧的分类。首尾循环切换、不自动播放；切换后默认主版本，A/B 按钮只切换**同一作品的视频版本**。未保存草稿通过 `navigateWithDraft` 守卫；快捷键 `Option + ←/→` 不在输入框中触发。

隔离回归：`npm run check:workbench-navigation`，覆盖精选首尾、分类顺序、搜索、快捷键、A/B、未保存保护、桌面门禁及正式文件不变。

## 本地保存和跨标签预览同步

服务端 `tools/cover-studio/server.mjs` 保存封面/海报后，通过仅允许指定本机 Origin 的 `GET /api/preview-events` SSE 通道通知已打开的本地 `5174` Vite 预览页。消息仅包含操作类型、作品 ID、视频版本 ID 和递增序号，不含视频内容、私有文件路径和令牌。前端 `src/utils/localPreviewArtwork.js` 利用 `useSyncExternalStore` 为指定图片添加版本查询参数，及时更新缓存。

`src/components/ProjectCard.jsx` 只刷新受影响的 3:4 封面；`src/components/CinemaPlayer.jsx` 只刷新对应视频版本的播放器海报，不重载视频弹窗。作品标题/排序等需要重新导入 JavaScript 数据模型的修改，会等到播放器关闭后才刷新整个本地网页。**生产 Netlify 不连接本机 SSE**。

右侧「发布与预览」中的低频「本地网页预览」指向 `works.html?category=...&project=...`；`src/components/WorksLibrary.jsx` 自动选分类、定位并短暂高亮对应卡片，随后清除临时作品参数，不自动播放。未保存标题、地址、视频版本和选帧草稿在关闭/切换时统一保护；弹窗焦点不得跑到背景层。

隔离验证：`npm run check:workbench-preview-sync` 和 `npm run check:workbench-draft-focus`。前者对隔离副本真实保存岳阳楼两种图片，并检查另一个已打开的网页立即更新且没有刷新整个页面。

## 作品历史（备份、预览、恢复）

- **历史限额：3 张/卡片，3 张/播放器视频版本**。只有真实存在的 WebP+JSON 配对才参与计算。服务重启时清理旧记录，之后每次保存/恢复也自动轮转，当前正式封面不计入。
- `tools/cover-studio/artwork-history.mjs` 按作品 ID、封面类型、视频版本扫描历史。只允许读取具有合法修订记录的特定 `<revision>-previous.webp`（海报包含版本 ID），校验文件 WebP 格式、大小、真实路径及匹配元数据。旧记录没有真实备份时绝不凭空生成图。
- `GET /api/artwork-history` 返回历史日期/预览地址及当前图片 SHA-256。`GET /artwork-history-image/<kind>/<projectId>/<revisionId>` 仅提供匹配合法元数据的 WebP 备份，不暴露本地文件绝对路径。
- `POST /api/restore-artwork` 需确认标志、预期当前 SHA-256、所选修订 ID，并校验作品/版本/实际画幅。保存当前图片作为**新的历史版本**后原子替换图片；发生错误时恢复原图和时间元数据。旧的 SHA-256 不匹配返回 409。
- `tools/cover-studio/library-history.js` 在现有全屏编辑区每种封面下提供「历史」小入口，左右对比当前图与旧图，再一键恢复；不新增导航 Tab。手机根据横竖比例适配。
- 首次替换 3:4 封面时，如果规范化目标尚不存在，也会先从当前原始封面源保存旧图，避免只有 JSON 记录却无法恢复。海报历史针对 A/B 版本隔离。
- 隔离验收命令：`npm run check:workbench-history`（备份与反向恢复、3:4 封面恢复、过期请求和跨版本拒绝、正式文件不变）；工作台仅面向桌面，不以手机工作台布局作为验收目标。

## 原比例播放器海报独立替换

作品编辑工作区同时展示 **3:4 卡片封面 / 播放器原比例海报**，选择某个版本后在同一个页面直接修改。原比例模式选择目标作品及 A/B 版本后，可通过 `/api/import-project-video` 直接从对应的本地 MP4 创建临时选帧会话，选帧与导出沿用 FFmpeg；`GET /project-poster/:id/:variant` 安全读取对应版本的当前海报供新旧对比。

明确确认后 `POST /api/associate-poster` 校验导出来源、作品 ID、版本 ID、原海报路径和时间点（防过期覆盖），以及新图比例是否与视频显示宽高一致。只原位更新对应 `player-posters/<category>/<MP4 English Stem>.webp` 并写入主视频的 `project-video-metadata.json` 或附加版本的 `auto-projects.json` 选帧来源和时间。旧海报保存在 `.cover-studio/project-revisions/poster-history/<ID>/`，失败时恢复；**不会修改 3:4 封面、MP4、其他版本或 ImageKit URL**。可导入相同比例的静态图片作为新海报，但绝不拉伸或裁切成播放器比例。

运行 `npm run check:cover-poster` 对旧作品主视频、工作台新增作品的 B 版本、比例错误拦截和桌面/手机界面做隔离测试。

## 排序持久化与恢复

排序保存请求由 `tools/cover-studio/project-order.mjs` 校验，拒绝缺失、重复、伪造 ID 及过期草稿；确认后原子更新 JSON，并将变更前后状态写到 `.cover-studio/project-revisions/`。统一作品库的封面拖拽松手立即保存，成功后可短暂撤销；旧式独立排序模块只在内部兼容流程中保留，不属于日常入口。

工作台首页默认呈现 **8 部精选**，另有四种分类 Tab。当前可见的作品卡片直接拖动、松手自动保存排序，成功后提供短暂撤销；非精选作品可点星标，明确选择要替换的精选，始终保持 8 个名额。分类内重排只改变该分类的相对顺序；搜索结果不允许拖动。保存后本地预览同步更新，必要时在 `http://127.0.0.1:5174/` 和 `works.html` 验证。不要恢复候选池、冗余「全部作品」Tab、独立排序保存条或「全部作品前 8 张锁定精选」规则。

## 岳阳楼末帧及同步修复

- 岳阳楼 MP4 容器时长约 133.955 秒，画面最后一帧实际约 133.867 秒。音频尾巴导致过去末端定位偶尔没有视频帧，海报的保存时间曾被误记为 0 秒。现在记录 FFprobe 帧数、帧率和末帧时间，使用 FFmpeg 解码最后两秒并留存真正最后一帧，而不是把容器最后时间交给普通快进截帧。
- 「尾帧」按钮使用 FFmpeg 真实末帧解码。前端靠近末帧时自动采用精确末帧；保存期间禁止关闭或切换 A/B 版本，避免数据写入成功却漏掉工作台刷新。
- 作品列表和播放器海报每次保存都使用新的带版本参数的本地图片路径。实际用户网站的云端视频上传与 Netlify 发布仍是独立流程。
- 隔离端到端验证命令：`npm run check:workbench-endframe`。使用有音频尾巴的素材隔离副本验证真实末帧、两种封面独立保存、保存期间的导航保护、图片刷新和历史限额；不修改正式素材。
