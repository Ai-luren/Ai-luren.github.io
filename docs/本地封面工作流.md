# 本地视频封面工作流

## 启动

在项目根目录运行 `npm run covers`，打开 <http://127.0.0.1:5190/>。
本机需要 `ffmpeg`、`ffprobe`，无需 API Key、云服务或新依赖。工具只监听 `127.0.0.1`，正式 Vite 构建不引用工具页面、上传接口或 FFmpeg 服务。

作品库预览另运行 `npm run dev -- --host 127.0.0.1 --port 5181`，打开 <http://127.0.0.1:5181/works.html>。

## 每条视频的操作

1. **选择本地 MP4**。工具复制原视频到 `.cover-studio/sessions/<会话ID>/`，显示时长、显示分辨率与比例，抽取 12 张带时间点的候选。此时没有默认选中画面，也不会导出封面。
2. **选择画面**。点击候选，或输入任意秒数后点击“提取该时间点”。时间轴和前后逐帧按钮用于微调；保留候选及手动提取的原尺寸 PNG。抽帧精度受视频帧率影响。
3. **调整构图**。Cover 裁切填满 3:4；Contain Blur 用模糊背景填满 3:4，前景保留完整画面。拖动预览或用水平/垂直滑块调整位置，方向键可微调。自行检查人物、产品、Logo、字幕。工具不会自动判断最佳构图。
4. **确认导出**。点击“确认使用此封面并导出”，将当前预览的 900×1200 PNG 像素交给本机 FFmpeg 编码为质量 90 的 WebP，避免浏览器与后端分别渲染造成裁切或模糊不一致。页面展示实际输出图片、完整路径、体积和下载按钮。导出不改变作品数据；修改画面或构图后必须重新确认导出。
5. **明确关联**。选择对应的已登记作品，核对当前封面，勾选替换确认，再点击“确认替换此作品封面”。新文件复制到 `assets/images/project-covers/custom/<作品ID>-<导出ID>.webp`，映射写入 `src/data/project-cover-overrides.json`。刷新作品库即可看到新封面。

已有封面图片可点击“导入现成封面”，跳过视频候选步骤，仍需预览和确认导出。

新作品尚未在 `src/data/projects.js` 登记时，先完成封面选择并导出，将视频、标题、分类与导出文件交给维护者登记；之后刷新工具中的作品列表即可关联。工具不自动创建作品、不推断标题/奖项，也不自动选第一帧或随机帧。

## 保留与恢复

- 本轮保护原有 8 件 `featured` 精选封面，界面与服务端均不允许替换；新作品和其他已登记作品可以手动关联。
- 原视频、原封面不覆盖、不删除。重复导出使用唯一 ID，旧文件保留。
- `.cover-studio/` 不进入 Git 或正式构建，包含导入副本、候选、手动原帧、导出及关联记录。工具不自动清理，使用久后可按自己的保留需求整理；删除前由人确认。
- 每次关联会在 `.cover-studio/association-<ID>.json` 保存修改前后的映射。若要恢复旧封面，维护者可在核对记录后恢复映射；空映射使用原有封面。不要删除原素材。
- 关闭启动工具的终端进程即可停止文件处理服务。正式网站只读取已确认封面文件及映射，不包含管理接口。
- 每个导出附带同名 JSON，记录来源、选帧和裁切参数；单个输入文件最大 2GB。HEVC 抽帧由本机 FFmpeg 处理，不依赖浏览器解码能力。

## 验证

`node scripts/check-cover-studio.mjs` 在系统临时目录创建独立项目副本，使用真实横屏和竖屏素材验证候选、手动选帧、拖动、两种模式、WebP 导出、确认关联、正式作品库显示及视频播放，不修改真实项目的封面映射。测试目录保留供人工复核，不自动删除。

项目仍运行 `npm run build`、`npm run check:i18n`、`node scripts/check-project-library.mjs` 和 `git diff --check`。确认关联的正式封面会按正常资源路径进入网站构建；工作目录、原始视频副本和本地工具本身不会。
