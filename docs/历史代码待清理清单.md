## 判定标准

- **候选**：静态入口暂时找不到直接引用、命名与现行含义不符，或有明显重复职责。
- **可以退休**：确认没有静态/动态引用、HTML 标签入口、测试夹具和历史恢复用途，构建与必要专项都通过；还需确认没有依赖其导出或 side effect 的脚本。
- **保持**：有生产职责，或属于数据迁移/恢复历史；即使文件小、名称不好，也不能直接删。
- **明确不在本轮范围**：整站 React 改写、全站 CSS 清理、工作台状态框架迁移、ImageKit/CDN 重构。

## 一次清理的标准操作

1. **证明有/无引用**：查 `import`、动态 `import()`、HTML script、Vite glob、工作台 `ssrLoadModule`、脚本、配置、测试和本地开发手册。
2. **区分“无直接 import”与“无人使用”**：手动页面地址、URL 参数、浏览器本地存储、外部脚本、恢复资产可能不会出现在静态依赖图里。
3. **确认退出方式**：保留 Git 历史与迁移记录；如果涉及数据/素材，写出备份和回滚方案；在独立分支只清理一个候选。
4. **安全回归**：`npm run build`、`npm run check:repo-layout`、`npm run check:plan`、候选相关专项、`git diff --check`。浏览器测试必须在导航前拦截第三方媒体与线上 Hero 的重复下载，不能为测试再耗尽账户额度。
5. **成功标准**：实际行为、封面加载、CSS、首帧、URL 深链与作品管理工作台数据保持一致，新的实现确实更容易理解；达不到就回滚该候选的更改。
