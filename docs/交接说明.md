# 项目交接说明

本项目的文档角色划分与历史快照清单请参见 [文档索引](./文档索引.md)。

## 运行与构建

需要 Node.js `^20.19.0` 或 `>=22.12.0`。从项目根目录运行：

```bash
npm ci
npm run dev
```

开发首页访问 <http://127.0.0.1:5174/>；全部作品页为 `/works.html`。正式构建运行 `npm run build`，输出到 `dist/`。Vite 使用相对资源路径，兼容 GitHub Pages 根路径和子路径部署。

## 页面与运行时结构

- `index.html` 是首页，包含页面章节、Hero 背景视频、全局样式、静态文案和滚动叙事。
- `src/main.jsx` 等待 `window.__gsapReady` 后挂载 `src/App.jsx`。
- `src/App.jsx` 将交互组件挂到首页预留节点：
  - `#projects-react-root` → `MagneticProjectArchive`，读取共享作品数据中的 8 件精选作品。
  - `CinemaPlayer` → 首页影院播放器，按当前精选顺序切换作品。
  - `#recognition-react-root` → `ImpactEvidence`，包含 8 张获奖图片网格与查看器、AI 平台展示和自媒体账号资料弹窗。自媒体使用单色平台标识，AI 平台展示使用彩色品牌标识。
  - `#footer-dock-react-root` → `FloatingDock`，提供复制操作、社交入口及粗指针下的 `ExternalLinkSheet` 确认。
  - `#experiments-react-root` → `ExperimentFlip` 三个站内项目详情，真实示例图片放在 `assets/images/lab/`，具体素材/外链/回归说明见 [AI 实验室与外链维护](./AI实验室与外链维护.md)；另有 `#hero-actions-react-root`、`#hero-title-react-root` 的 Hero 交互。
  - `VideoPostProcess` → 只处理首页背景视频。
- `works.html` 是独立的第二个 Vite 构建入口；`src/works-main.jsx` 挂载 `WorksLibrary`，按当前筛选结果切换作品并共用影院播放器。
- 首页和作品库保持独立页面及各自入口；靠近精选作品区域时由 src/navigation/pagePrefetch.js 低优先级预取作品库 HTML / JS / CSS，在作品库空闲时预取首页资源，不预取 ImageKit 视频或作品封面。两页在文档头部启用浏览器原生跨文档 View Transition，共用 `src/styles/page-transitions.css` 的轻量淡出/淡入规则。该效果只柔化页面切换，不会把作品库变成单页应用，也不消除目标页面加载；浏览器不支持时按普通链接导航，减少动态偏好下动画时长降至 1ms。
- `src/data/projects.js` 汇总原有 14 件作品与 `src/data/auto-projects.json` 的工作台新增作品（当前 18 件、21 条视频）；旧作品追加的视频版本记录在 `src/data/legacy-video-variants.json`。`src/data/project-order.json` 的 `featured` 是首页固定 8 个名额的可替换精选名单，`all` 独立决定完整作品的显示顺序，两者互不强制同步；精选仍为手机每页 4 件，播放器跟随各自顺序。`works.html` 默认显示商业广告，四分类按钮切换，不显示「全部」分类按钮。视频比例和海报元数据见 `src/data/project-video-metadata.json`。
- `src/styles/navigation.css` 提供作品库、影院和奖项查看器共用的导航规则；作品库普通页左侧为 A+ 圆形箭头 +「首页 / Home」，指向 ./index.html Hero 首屏，桌面中央的「精选作品 / Featured」另跳 #projects；详情查看器仍使用创作者头像。基础视觉 Token 在 `src/styles/card-surfaces.css` 与 `src/styles/apple-system.css`。

## 关键媒体与本地工具

- 桌面 Hero：`assets/videos/hero/hero.mp4`。
- 移动 Hero（720px 及以下）：`assets/videos/hero/hero-mobile.mp4`。
- 作品列表 3:4 封面：`assets/images/project-covers/<category>/<English Title>.webp`，按四分类英文目录存放；替换前备份旧图。
- 原比例播放器海报：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`；实际显示宽高与海报映射见 `src/data/project-video-metadata.json`。
- 原有作品主版本的 ImageKit `tr:orig-true` 地址位于 `src/data/legacy-imagekit-urls.json`，旧作品新增版本位于 `legacy-video-variants.json`，工作台新增作品（目前 ID 16–19）的主视频与扩展版本位于 `auto-projects.json`；本地 Vite 从 `assets/videos/works/` 读取原片，不请求 ImageKit；正式构建不会复制本地作品原片。
- `assets/videos/works/` 保存 18 部作品对应的 21 条本地 MP4，文件名按英文作品标题维护，已由 `.gitignore` 排除，供本地开发播放，不进正式构建。上传源片目录与项目视频目录分离；不可把本地路径当线上 URL，也不要全局忽略 `*.mp4`（Hero 视频要参与构建）。
- `tools/cover-studio/` 是独立的本地作品工作台，通过 `npm run covers` 启动在 `127.0.0.1:5190`，不参与 Vite 正式构建。导入、导出和历史保存在 Git 忽略的 `.cover-studio/`；可恢复的归档状态存在 `src/data/archive-state.json`。归档不会删除视频或线上文件，重新部署才会影响公开作品列表。
- 页面使用系统字体栈；`vendor/` 保留 GSAP 与 ScrollTrigger 静态脚本。

## 维护约定

- 修改首页结构或文案时编辑 `index.html`；精选成员、精选顺序及全部作品分类排序由 `npm run covers` 的作品库直接拖拽排序、点击精选星标替换维护，分别写入 `src/data/project-order.json` 的 `featured` 和 `all`，**不要再修改 `projects.js` 的固定数组或强制前八项锁定**。新增作品由工作台写 `auto-projects.json`。
- 新增作品先核对真实标题、分类、封面和视频身份；未选择前不进入首页 8 件精选，奖项未证实则保持空值。一个项目允许多个 A/B 版本，共用一张作品卡。
- 新作品及新视频版本通过 `npm run covers` 选帧生成播放器原比例海报；更换已有作品的 3:4 卡片封面不会改播放器海报。旧 `scripts/generate-player-media.mjs` 仍输出中文哈希文件名，**不适用于现行四分类目录，勿作为常规维护命令运行**；媒体规格、独立海报与回归规则见 [播放器媒体维护](./播放器媒体维护.md)。
- 封面与新增作品按 [工作台操作教程](./本地封面工作台使用教程.md) 处理。工作台按用户选择的画面精确取帧，无需自动生成 12 张候选；保存时备份原图并写入 WebP；可直接导入 PNG/JPG/WebP，原视频和旧封面必须保留。
- 页面语言由现有 i18n 状态管理，导航共用 B+++ 双分段语言控件（手机「中 / EN」、桌面「中文 / EN」）。共用导航、关闭和返回规范见 [设计规范](./设计规范.md)；媒体换片与加载规则见 [播放器媒体维护](./播放器媒体维护.md)。
- 联系方式与社交入口由 `FloatingDock.jsx` 渲染；邮箱、电话和微信操作维持既有复制/二维码行为。社交站外入口在粗指针/手机端先显示 `ExternalLinkSheet` 再跳转，桌面保留 Hover 提示和原生新标签访问；具体见 [AI 实验室与外链维护](./AI实验室与外链维护.md)。
- 获奖画廊一次展示 8 张：≥1280px 八列，≤1279px 四列两排；手机仅显示图片，完整信息在查看器中。详见 [设计规范](./设计规范.md)。
- 修改字体、颜色、动效或材质时，以唯一的 [`设计规范`](./设计规范.md) 和当前生产源码为准。

## 常用测试入口

- 日常快速检查：`npm run check:smoke`（构建、素材、排序和媒体安全）、`npm run check:workbench-core`（含回收站安全、版本、选帧、历史的工作台核心流程）；`npm run check:project` **仅依次执行这两组快速检查**，并非全量深度测试。
- 上线前对抗性检查：`npm run check:site-full`（独立生产预览下的网站深测）、`npm run check:workbench-full`（隔离项目内的工作台深测）；`npm run check:adversarial` 依次运行两组深测。
- 深测结果写入 Git 忽略的 `.audit/adversarial-qa-20261108/latest-*-check.json`。涉及写入的测试只能使用隔离项目，必须拦截真实 ImageKit CDN 请求。遇到失败先判断是否为页面问题、测试数据过期还是加载时序问题，不得删掉断言凑通过率。
- 原有细粒度脚本继续用于问题定位；修复的测试与验收结果详见本地 `.audit/adversarial-qa-20261108/TEST_SUITE_REPAIR.md`（不随 Git 发布）。

## 验收截图

使用 `scripts/capture-final-review.mjs` 对正式构建的本地预览取证，不能只验证开发模式：Vite 提取共享 CSS 后的顺序可能不同。先运行 `npm run build`，再运行 `npm run preview -- --host 127.0.0.1 --port 5182 --strictPort`，另一个终端执行：

```bash
PORTFOLIO_URL=http://127.0.0.1:5182/ \
REVIEW_SCREENSHOTS="$(dirname "$PWD")/final-review-screenshots" \
node scripts/capture-final-review.mjs
```

输出目录必须在仓库外。脚本等待 React、字体、逐屏滚动与动画、普通图片和 CSS 背景图解码，并输出中文/英文桌面与手机全页及局部截图、播放器与荣誉查看器截图和 `browser-verification.json`（HTTP、Console、解码、DOM 与 Hero 状态）。全页截图中的固定视频背景只代表截图当时的一帧；滚动叙事请结合 Hero 和章节局部视口截图判断。脚本不点击播放，并阻断且断言没有 ImageKit 视频请求。
