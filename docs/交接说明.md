# 项目交接说明

## 运行与构建

需要 Node.js `^20.19.0` 或 `>=22.12.0`。从项目根目录运行：

```bash
npm ci
npm run dev
```

开发首页访问 <http://127.0.0.1:5174/>；全部作品页为 `/works.html`。正式构建运行 `npm run build`，输出到 `dist/`。Vite 使用相对资源路径，兼容 GitHub Pages 根路径和子路径部署。

## 部署配置边界

仓库中 `.github/workflows/deploy-pages.yml` 只在 `main` 分支推送或手动触发时构建并发布 GitHub Pages。`netlify.toml` 声明 `npm run build` 和 `dist` 发布目录。Cloudflare Pages、Vercel 与 Netlify 的 Git 连接、预览分支和生产分支设置需要在各平台后台核对，仓库文件不能证明当前账户连接状态。

## 页面与运行时结构

- `index.html` 是首页，包含页面章节、Hero 背景视频、全局样式、静态文案和滚动叙事。
- `src/main.jsx` 等待 `window.__gsapReady` 后挂载 `src/App.jsx`。
- `src/App.jsx` 将交互组件挂到首页预留节点：
  - `#projects-react-root` → `MagneticProjectArchive`，读取共享作品数据中的 8 件精选作品。
  - `CinemaPlayer` → 首页影院播放器，按当前精选顺序切换作品。
  - `#recognition-react-root` → `ImpactEvidence`，包含奖项图片查看器、平台 Logo 和内容发布证据。
  - `#footer-dock-react-root` → `FloatingDock`，提供社交入口和复制操作。
  - `#experiments-react-root`、`#hero-actions-react-root`、`#hero-title-react-root` → AI 实验室和 Hero 交互。
  - `VideoPostProcess` → 只处理首页背景视频。
- `works.html` 是独立的第二个 Vite 构建入口；`src/works-main.jsx` 挂载 `WorksLibrary`，按当前筛选结果切换作品并共用影院播放器。
- `src/data/projects.js` 是首页和全部作品页的唯一作品数据源；分类、视频比例元数据及播放器海报分别见 `src/data/projects.js` 和 `src/data/project-video-metadata.json`。
- `src/styles/navigation.css` 提供作品库、影院和奖项查看器共用的导航规则；基础视觉 Token 在 `src/styles/card-surfaces.css` 与 `src/styles/apple-system.css`。

## 关键媒体与本地工具

- 桌面 Hero：`assets/videos/hero/hero.mp4`。
- 移动 Hero（720px 及以下）：`assets/videos/hero/hero-mobile.mp4`。
- 作品列表封面：`assets/images/project-covers/`；新增作品封面：`assets/images/project-covers/library/`；确认替换的封面：`assets/images/project-covers/custom/`。
- 播放器静止海报：`assets/images/player-posters/`；视频尺寸与海报对应关系：`src/data/project-video-metadata.json`。
- 当前 15 件作品使用 `src/data/projects.js` 中的 ImageKit `tr:orig-true` MP4 地址。若某件作品未配置 ImageKit 地址，Vite 开发模式可用 `assets/videos/works/` 作为本地兜底；正式构建不会复制作品原片。
- `assets/videos/works/` 的中文原片和根目录 `local-media CDN/` 的英文上传副本均由 `.gitignore` 排除。不得将本地上传副本当作网页 URL，也不要添加全局 `*.mp4` 忽略规则；Hero 视频需要纳入构建。
- `tools/cover-studio/` 是单独的本地维护工具，通过 `npm run covers` 启动在 `127.0.0.1:5190`。它使用本机 FFmpeg，不属于正式 Vite 页面或构建入口。导入副本、候选帧和历史保存在被忽略的 `.cover-studio/`，不会随网站部署。
- 页面使用系统字体栈；`vendor/` 保留 GSAP 与 ScrollTrigger 静态脚本。

## 维护约定

- 修改首页结构或文案时编辑 `index.html`；修改全部作品与精选数据时编辑 `src/data/projects.js`，不要维护第二份作品清单。
- 新增作品先核对真实标题、分类、封面和视频身份；`featured` 默认设为 `false`。新增作品未获得确认的奖项保持空值。
- 新增视频比例或播放器海报时运行 `node scripts/generate-player-media.mjs --id=<作品ID> --time=<秒>`，生成元数据与静止海报；列表 3:4 封面不能代替不同比例的视频海报。
- 新封面按 [`本地封面工作流`](./本地封面工作流.md) 操作；工作台不会自动选帧或替换。原视频和旧封面必须保留。
- 页面语言由现有 i18n 状态管理。播放器换片、切换语言、关闭和后退行为见 [`影院导航维护`](./影院导航维护.md)。
- 联系方式与社交入口由 `FloatingDock.jsx` 渲染；邮箱、电话和微信按钮执行复制，其余有效入口跳转外部主页。修改前先核对 `src/components/FloatingDock.jsx` 中当前配置。
- 修改字体、颜色、动效或材质时先看 [`设计规范`](./设计规范.md) 与 [`设计系统统一说明`](./设计系统统一说明.md)。

## 验证

```bash
npm run build
npm run check:i18n
node scripts/check-project-library.mjs
node scripts/check-mobile-project-gestures.mjs
node scripts/check-mobile-menu-focus.mjs
node scripts/check-cover-studio.mjs
git diff --check
```

作品库与移动端回归脚本可用 `PORTFOLIO_URL` 指向当前 Vite 地址。若 `check:i18n` 自动启动服务超时，先启动 `./node_modules/.bin/vite --host 127.0.0.1 --port 5199 --strictPort`，再运行 `npm run check:i18n`。更细的媒体和影院检查命令见 [`播放器媒体维护`](./播放器媒体维护.md) 与 [`影院导航维护`](./影院导航维护.md)。
