# 播放器比例与封面维护

作品卡片仍使用现有 3:4 `cover`。影院弹窗单独读取 `videoWidth`、`videoHeight` 和可选的 `playerPoster`，不裁切或拉伸原视频。播放器海报文件使用网页中文作品名加内容哈希命名，例如 `海外无线耳机 AI 场景广告-<哈希>.webp`；作品名以 `src/data/projects.js` 为准。

## 生成方式

新增或更新作品视频后，在项目根目录运行：

```bash
node scripts/generate-player-media.mjs
```

只生成指定作品，并指定原片选帧时间（秒）：

```bash
node scripts/generate-player-media.mjs --id=09 --time=10.131
```

脚本从共享作品数据定位本地视频，使用 FFprobe 读取显示宽高（考虑像素比例与旋转），使用 FFmpeg 提取完整画幅的 WebP。输出文件按中文作品名和内容哈希命名，保留旧文件，不修改卡片封面、作品标题、奖项或视频原片。

- 数据：`src/data/project-video-metadata.json`。
- 图片：`assets/images/player-posters/`。
- `projects.js` 将这些数据合并到共享作品记录，生成生产构建可用的图片地址。
- 本地 MP4 不随本流程进入构建；以后配置 ImageKit 时应保持视频与元数据对应。

未显式指定时间时，优先复用当前已关联封面的 `.cover-studio/exports/` 选帧记录；记录不存在时保留之前的播放器选帧时间，新作品默认取第 1 秒（极短片取时长一半）。这些仅是播放器的静止预览，不代表重新确定作品卡片封面。可随时使用 `--time` 指定更合适的完整画面。

## 播放器行为

弹窗在显示前使用预生成的宽高计算尺寸。`loadedmetadata` 用于核对；已有元数据不在播放时改变比例。若控制台提示规格过期，请重新运行生成脚本。

用户点击播放后，等待视频帧实际可呈现，再以 180ms 淡出播放器封面。支持减少动画偏好的浏览器直接切换。未配置播放器封面时，在同一稳定容器内完整显示原卡片封面；可能留黑，但不会拉伸。没有提前登记宽高时，显示明确的规格读取占位，再按真实元数据进入播放器，建议发布前补齐规格。

播放器封面和视频共同使用容器圆角，桌面复用 `--portfolio-content-radius`（18px），手机从同一内容圆角变量限定为 14–16px（当前 16px）。关闭时暂停并释放视频地址。

## 验证

```bash
node scripts/check-cinema-stability.mjs
node scripts/check-cinema-layout.mjs
node scripts/check-cinema-playback.mjs
npm run build
npm run check:i18n
node scripts/check-project-library.mjs
git diff --check
```

当前真实素材覆盖 16:9 与 9:16 等比例，尚无真实 3:4 视频。打开和切换作品时播放器不设置 `src`，因此布局脚本根据作品预登记的 `videoWidth` / `videoHeight` 检查画幅，并断言 `readyState=0`、暂停且没有媒体请求。稳定性测试在明确点击播放后使用共享 Playwright 媒体保护拦截 ImageKit 地址，提供本地轻量视频并延迟请求，再逐帧比较首屏、metadata 加载及首帧呈现期间的播放器位置和尺寸；测试桌面 1440px 和手机 393px，不连接真实 CDN。

## 自动化测试不消耗 ImageKit 流量

Playwright 入口统一使用 `scripts/lib/safe-media.mjs` 的 `createSafePage` / `createSafeContext`。这两者在打开页面前拦截所有 ImageKit 域名请求：对 MP4 返回 `scripts/fixtures/` 内 12 秒的本地横屏/竖屏测试视频，非 MP4 请求阻断；不会下载远程视频，也不会产生 CDN 带宽或 VPU 消耗。

可运行 `node scripts/check-safe-media-guard.mjs` 来确认本地媒体实际能播放并且访问被拦截。所有常规回归测试均应使用这些保护函数。若未来必须验证 ImageKit 在线播放，先获得用户明确授权，进行一次性人工检查，不要为常规测试打开自动化真实 CDN 访问。

该保护只存在于 `scripts/` 中，不影响真实网站运行或正式部署。

**手动本地预览**：`npm run dev` 时播放器自动指向已存在的 15 部本地作品 MP4；不会调用 ImageKit。正式 `npm run build` / Netlify 部署则保留 ImageKit 原片 URL。开发者若缺少本地 MP4，应补齐本地文件，不允许自动回退到远程 CDN。

## Hero 移动端首帧与加载兜底

- `assets/images/hero-first-frame-mobile.webp`（640×360）和 `assets/images/hero-first-frame-desktop.webp`（1280×720）直接从当前 Hero 原片约 0.4 秒位置截取；更换 `assets/videos/hero/hero-mobile.mp4` 或 `hero.mp4` 时，同步重新生成这两张静态海报，以免加载切换时画面跳动。
- `index.html` 在 `#video-bg` 设置响应式背景首帧，`#hero-video` 另有原生 `poster`。移动端在首次打开时立即 `warmVideo()`，不再依赖触摸或滚动事件才获取视频首帧；桌面端保留延迟预热，降低无谓下载。
- `VideoPostProcess.jsx` 只在真实视频帧解码并完成第一次 WebGL 渲染后添加 `is-webgl-ready`，避免黑色画布遮挡原生视频；WebGL 不可用时仍回退到原生视频及海报。不改变作品视频的 ImageKit 配置。
- 运行 `npm run check:hero-first-frame`（拦截本地 Hero MP4 模拟视频加载失败，并检查正常解码与 WebGL）；同时运行 `npm run check:clipboard` 确保剪贴板权限拒绝时不会误报复制成功。真实 iOS Safari 仍需用手机实测一次。

## 手机端滚动跟手与背景稳定性（2026-10-26）

- 首页滚动叙事仍为 15 秒；桌面保持原来 1280×720 / 30fps 的 `hero.mp4`、滚动定位逻辑和 60fps WebGL。
- 手机 `hero-mobile.mp4` 使用 640×360 / 30fps H.264，9 帧（约 0.3 秒）一关键帧、无 B 帧、faststart；约 2.9MB，原版 1 秒 GOP 文件本地备份在 `.audit/mobile-scroll-investigation-20261026/`。更换素材时必须保留适合滚动定位的关键帧密度。
- `index.html` 手机端 seek 上限约 20 次/秒，当前定位未完成不再次打断，停手后纠正到真实滚动时间；手机固定背景使用 `100lvh`，窗口只有高度变化时不刷新 GSAP，宽度变化（旋转）仍刷新。
- `VideoPostProcess.jsx` 手机滚动 WebGL 上限 30fps、静止 20fps；桌面行为不变。
- `npm run check:mobile-scroll-response` 检查 390/430/1440px 的 seek、进度、resize、触控视口与媒体安全。**真实 iOS Safari 的地址栏及跟手感仍需用手机验收**。

## 手机端 WebGL 图形上下文恢复

`VideoPostProcess.jsx` 在 `webglcontextlost` 时阻止失效画布遮挡背景，取消旧帧循环，立即恢复原生视频层（视频自身含 `poster`，父层含静态首帧）；在 `webglcontextrestored` 后重新构建 OGL renderer / texture / shader 并确认完成新帧绘制后再显示 WebGL。上下文始终无法恢复时，继续保持原生视频/海报兜底。不得通过重新请求 ImageKit 视频来恢复 GPU。

运行 `npm run check:webgl-recovery` 在手机 390px 与桌面 1440px 模拟 GPU context loss + restore，检查兜底、恢复和资源地址不变。真实 iPhone Safari 仍需要人工验证。
