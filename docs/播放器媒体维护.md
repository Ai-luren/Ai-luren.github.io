# 播放器比例与封面维护

作品卡片使用 3:4 封面；播放器独立读取 `videoWidth`、`videoHeight` 与 `playerPoster`，按实际画幅显示，不把卡片封面拉伸进播放器。静态海报按四分类目录和英文 MP4 文件名存放；原有主版本元数据由 `src/data/project-video-metadata.json` 维护。新增作品的附加版本在 `src/data/auto-projects.json` 的 `variants[]`，原有作品追加版本在 `src/data/legacy-video-variants.json`。

## 选帧与媒体目录

- **新增作品**：使用 `npm run workbench`，导入视频并人工选择时间点。同一选帧分别导出 900×1200 的 3:4 卡片封面和按真实显示比例（包括 SAR）生成的播放器原比例海报。
- **追加版本**：原有作品和工作台新增作品均可添加 MP4 版本及独立播放器海报，主视频／主海报不被覆盖；版本间可采用不同画幅，单作品最多 8 个版本。
- **仅更换卡片封面**：原位更新 `assets/images/project-covers/<category>/<English Title>.webp`，不会修改播放器海报或其选帧时间；上一版进入 `.cover-studio/project-revisions/cover-history/`。
- **修改英文标题**：工作台同时同步本地 MP4、卡片封面和播放器海报的文件名及 JSON 引用；原始上传素材和 ImageKit 地址不改。
- **播放器海报目录**：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`，与每个 MP4 版本一一对应。四分类为 `commercial`、`short-film`、`social`、`visual`。

**独立更换原比例海报**：工作台「更换作品封面 → 播放器海报 · 原比例」可选择任意作品及主版本／A/B 视频版本，从该版本本地 MP4 选帧或导入画幅一致的图片，比较旧海报后单独替换。原图备份、比例校验与选帧时间同步由工作台管理；运行 `npm run check:cover-poster`。旧的播放器海报生成脚本（原 `scripts/generate-player-media.mjs`）不兼容现行四分类目录，已退出活动脚本目录；源码留存于本地 `.audit/phase1-safe-cleanup-20261112/retired-scripts/` 和 Git 历史。**只使用工作台生成或替换海报**。

## 播放器行为

弹窗在显示前使用预生成的宽高计算尺寸。`loadedmetadata` 用于核对；已有元数据不在播放时改变比例。未播放时的总时长从 `src/data/project-video-metadata.json` 与扩展版本的 `videoDuration` 字段读取，本地素材通过 `ffprobe` 登记，不请求线上 MP4；工作台新增作品／版本时复用导入视频时读取到的 `session.metadata.duration`，实际开始播放后由媒体元素自身的时长覆盖显示。若控制台提示规格过期，请重新核对元数据。

手机端首次打开即显示下方 44px 的播放/暂停小按钮（位置与播放后保持一致），中央首播按钮仍保留。手机端播放开始后，直接轻点视频画面可暂停，再次轻点继续；画面触摸和底部小按钮的播放／暂停操作会在中央显示750ms 的短暂圆形图标反馈：0-150ms 淡入同时放大（78%→106%）、150-600ms 完全显示并保持 106%、600-750ms 淡出同时缩小（106%→80%），透明度与缩放关键帧严格同步：透明度与缩放分别采用 Material 风格的非对称贝塞尔曲线（进入 `cubic-bezier(0,0,.2,1)`、退出 `cubic-bezier(.4,0,1,1)`），并自动淡出（降低动态效果偏好时缩短反馈），不遮挡或截获触摸；加载中、切换版本或失败状态不得误触发二次播放。桌面仍使用浏览器原生视频控件，全屏仍遵循系统原生控制。手机端倍速使用与影院一致的居中深色薄纱玻璃横向分段胶囊（1×／1.25×／1.5×／2×，四档并排、选中项复用中性玻璃填充；直接使用 `--portfolio-glass-surface` / `--portfolio-glass-blur`，减少透明度或不支持背景模糊时降级为 `--portfolio-glass-solid`），菜单悬浮在视频下方控制栏上方并相对整条控制栏居中，不用系统白色原生选择器或遮挡画面的四行竖排菜单；支持点击外部、Esc、方向键、Home/End 和选择后恢复焦点。回归 `npm run check:cinema-controls`。

用户点击播放后，等待视频帧实际可呈现，再以 180ms 淡出播放器封面。支持减少动画偏好的浏览器直接切换。未配置播放器封面时，在同一稳定容器内完整显示原卡片封面；可能留黑，但不会拉伸。没有提前登记宽高时，显示明确的规格读取占位，再按真实元数据进入播放器，建议发布前补齐规格。

播放器封面和视频共同使用容器圆角，桌面复用 `--portfolio-content-radius`（18px），手机从同一内容圆角变量限定为 14–16px（当前 16px）。关闭时暂停并释放视频地址。


## 影院播放状态与浏览顺序

- **传入顺序**：首页由 `src/App.jsx` 向 `CinemaPlayer` 传入 `FEATURED_PROJECTS`，严格遵循 `project-order.json.featured` 的 8 件精选排序（手机 4+4）；作品库由 `WorksLibrary.jsx` 传入当前可见筛选结果，换片不改变筛选类别或 URL。**影院首尾不循环**，对应上一部／下一部按钮禁用；此规则不同于本地工作台跨分类循环导航。
- **同一作品内的版本顺序**：`src/data/project-version-order.json` 独立于作品卡片顺序，`projectVideoVersions` 使用稳定版本 ID 排序。影院首次打开默认第一条未归档视频（即使该条不是 `main`，或 `main` 已在回收站），对应的原比例海报也必须先解码；如果缺失则回退已解码的作品卡片封面。排序不会改变真实媒体元数据、主版本身份与视频 URL。
- **组件生命周期**：`CinemaPlayer` 外层 key 只区分打开／关闭，不随作品 ID 更换整个弹层；仅视频与静态海报随作品重建。调用已有 `toggleLang` 切换语言，不重建正在播放的视频、不重置进度。换片先暂停旧视频、保持旧海报或已显示视频帧，待新海报解码成功后才释放旧资源并替换画面；失败时先解码下一部的卡片封面兜底，两张都失败则保留旧画面，不再使用原本 1.5 秒的强制替换。新片暂停在 0 秒。
- **加载边界**：从作品卡片 hover、触摸或键盘聚焦时仅预热独立播放器海报，点击后待图片解码再打开弹窗；失败回退当前 3:4 卡片封面。A/B 视频版本切换同样先完整解码将显示的新海报，未就绪时保留旧帧并显示轻量准备状态；视觉选中线采用克制的 Framer Motion 弹簧、文字轻上移 1px，未开始播放的海报交接用 340ms 的旧海报淡出与 8px 方向位移（新海报已预先解码，绝不黑屏；若已开始播放，禁止盖上旧海报）；快速取消、关闭或切换作品会使旧异步响应失效，8 秒超时后回退已解码的卡片封面，不能直接替换为尚未加载的图片。打开或换片时 video 保持 `paused`、`currentTime=0`、`readyState=0` 且不设置 `src`；用户明确点击播放之后才加载媒体或等待 `loadedmetadata`，不得自动请求 ImageKit。
- **带宽策略**：播放器尚未点击播放时不预请求相邻作品的原比例海报，避免在移动网络中与当前 MP4 首帧争抢下载带宽；上一部／下一部按钮在悬停或键盘聚焦时预热对应海报。MP4 的 `preload="none"` 和首帧呈现前保留海报的规则不变。
- **退出与后台**：点击关闭立即暂停并释放视频地址，焦点恢复原触发卡片；切换页面或进入后台暂停声音。关闭与浏览器原有 `popstate` 不额外增加历史记录。播放器画面与控制区不应因切换语言、海报解码或短视口回流跳动。
- **专项检查**：`node scripts/checks/site/check-media-presentation.mjs`、`node scripts/checks/site/check-cinema-playback.mjs`、`node scripts/checks/site/check-cinema-stability.mjs`、`node scripts/checks/site/check-project-library.mjs`；`npm run check:cinema-local` 专门在本地 Vite 开发地址（默认 5174）使用真实本地 MP4，测 390/1440px、2.6 秒版本海报延迟、3.5 秒换片延迟、1.45 秒视频缓冲、404、快速取消及播放中切换，断言无真实 ImageKit 请求。此项只用于开发环境，不纳入生产预览 `check:site-full`（生产模式按配置会指向 ImageKit）。导航与弹窗见 [设计规范](./设计规范.md)。

## 自动化测试不消耗 ImageKit 流量

Playwright 入口统一使用 `scripts/lib/safe-media.mjs` 的 `createSafePage` / `createSafeContext`。这两者在打开页面前拦截所有 ImageKit 域名请求：对 MP4 返回 `scripts/fixtures/` 内 12 秒的本地横屏/竖屏测试视频，非 MP4 请求阻断；不会下载远程视频，也不会产生 CDN 带宽或 VPU 消耗。

可运行 `node scripts/checks/site/check-safe-media-guard.mjs` 来确认本地媒体实际能播放并且访问被拦截。所有常规回归测试均应使用这些保护函数。若未来必须验证 ImageKit 在线播放，先获得用户明确授权，进行一次性人工检查，不要为常规测试打开自动化真实 CDN 访问。

该保护只存在于 `scripts/` 中，不影响真实网站运行或正式部署。

**手动本地预览**：`npm run dev` 时播放器优先指向 `assets/videos/works/` 内的 18 部作品、22 条本地视频；不会调用 ImageKit。正式 `npm run build` / Netlify 部署则保留各版本配置的 ImageKit 原片 URL。开发者若缺少本地 MP4，应补齐本地文件，不允许自动回退到远程 CDN。

## Hero 移动端首帧与加载兜底

- `assets/images/hero-first-frame-mobile.webp`（640×360）和 `assets/images/hero-first-frame-desktop.webp`（1280×720）直接从当前 Hero 原片约 0.4 秒位置截取；更换 `assets/videos/hero/hero-mobile.mp4` 或 `hero.mp4` 时，同步重新生成这两张静态海报，以免加载切换时画面跳动。
- `index.html` 在 `#video-bg` 设置响应式背景首帧，`#hero-video` 另有原生 `poster`。当前手机与桌面均在首页脚本初始化时立即执行 `warmVideo()`，以本地 Hero MP4 为背景媒体；作品播放器则维持点击播放后才请求对应视频，不可混淆。
- `VideoPostProcess.jsx` 只在真实视频帧解码并完成第一次 WebGL 渲染后添加 `is-webgl-ready`，避免黑色画布遮挡原生视频；WebGL 不可用时仍回退到原生视频及海报。不改变作品视频的 ImageKit 配置。
- 运行 `npm run check:hero-first-frame`（拦截本地 Hero MP4 模拟视频加载失败，并检查正常解码与 WebGL）；同时运行 `npm run check:clipboard` 确保剪贴板权限拒绝时不会误报复制成功。真实 iOS Safari 仍需用手机实测一次。

## 首页浏览滚动位置稳定性（2026-11-11）

- **使用浏览器原生初始定位**：首次无锚点导航自然从 Hero 顶部开始；直接访问章节锚点时由现有 `alignInitialHash` 对齐标题。首页代码不再主动调用 `scrollTo(0,0)`；尤其不能在迟到的 `window.load` 或 `pageshow` 回调中重置滚动位置，否则弱网下 Hero MP4 加载结束会把正在阅读的访客拉回顶部。

## 手机端 WebGL 图形上下文恢复

`VideoPostProcess.jsx` 在 `webglcontextlost` 时阻止失效画布遮挡背景，取消旧帧循环，立即恢复原生视频层（视频自身含 `poster`，父层含静态首帧）；在 `webglcontextrestored` 后重新构建 OGL renderer / texture / shader 并确认完成新帧绘制后再显示 WebGL。上下文始终无法恢复时，继续保持原生视频/海报兜底。不得通过重新请求 ImageKit 视频来恢复 GPU。

运行 `npm run check:webgl-recovery` 在手机 390px 与桌面 1440px 模拟 GPU context loss + restore，检查兜底、恢复和资源地址不变。真实 iPhone Safari 仍需要人工验证。

## 多版本播放器

原有作品与工作台新增作品都支持添加视频版本。主版本沿用既有 `project.videoUrl`、`videoWidth`、`videoHeight`、`playerPoster`；新增作品的扩展版本保存在 `auto-projects.json`，原有作品扩展版本保存在 `legacy-video-variants.json`，各自保存本地路径、线上 URL、画幅及海报。中英文版本名称独立于作品标题；右侧「作品管理」按作品统一名称→视频版本排列；单击版本标签切换，所选视频中英文名称输入框常驻显示，修改后才出现保存与撤销；保存后同步当前视频标题，且不修改上方共用作品名。标签行最右的归档图标仅处理所选视频，至少保留一条可用视频。添加视频版本的入口仍位于同一区域。版本名称由本地 `POST /api/update-version-label` 保存到相应 JSON 与修订历史，不请求 ImageKit，也不发布网站。播放器内切换先暂停旧视频、保留已显示的视频帧或海报，解码新版本海报（失败回退卡片封面）后才释放旧视频 `src`、正式更新版本；新版本仍在用户点击播放后才加载。版本按钮不创建第二条导航，也不影响作品上一部／下一部。
