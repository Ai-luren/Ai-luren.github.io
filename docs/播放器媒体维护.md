# 播放器比例与封面维护

作品卡片使用 3:4 封面；播放器独立读取 `videoWidth`、`videoHeight` 与 `playerPoster`，按实际画幅显示，不把卡片封面拉伸进播放器。静态海报按四分类目录和英文 MP4 文件名存放；原有主版本元数据由 `src/data/project-video-metadata.json` 维护。新增作品的附加版本在 `src/data/auto-projects.json` 的 `variants[]`，原有作品追加版本在 `src/data/legacy-video-variants.json`。

## 选帧与媒体目录

- **新增作品**：使用 `npm run workbench`，导入视频并人工选择时间点。同一选帧分别导出 900×1200 的 3:4 卡片封面和按真实显示比例（包括 SAR）生成的播放器原比例海报。
- **追加版本**：原有作品和工作台新增作品均可添加 MP4 版本及独立播放器海报，主视频／主海报不被覆盖；版本间可采用不同画幅，单作品最多 8 个版本。
- **仅更换卡片封面**：原位更新 `assets/images/project-covers/<category>/<English Title>.webp`，不会修改播放器海报或其选帧时间；上一版进入 `.cover-studio/project-revisions/cover-history/`。
- **修改英文标题**：工作台同时同步本地 MP4、卡片封面和播放器海报的文件名及 JSON 引用；原始上传素材和 ImageKit 地址不改。
- **播放器海报目录**：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`，与每个 MP4 版本一一对应。四分类为 `commercial`、`short-film`、`social`、`visual`。

**独立更换原比例海报**：作品管理工作台中选择作品 →「封面与海报」→「播放器海报 · 原比例」可选择任意作品及主版本／A/B 视频版本，从该版本本地 MP4 选帧或导入画幅一致的图片，比较旧海报后单独替换。原图备份、比例校验与选帧时间同步由工作台管理；运行 `npm run check:cover-poster`。旧的播放器海报生成脚本（原 `scripts/generate-player-media.mjs`）不兼容现行四分类目录，已退出活动脚本目录；源码留存于本地 `.audit/phase1-safe-cleanup-20261112/retired-scripts/` 和 Git 历史。**只使用工作台生成或替换海报**。

## 播放器行为

弹窗在显示前使用预生成的宽高计算尺寸。`loadedmetadata` 用于核对；已有元数据不在播放时改变比例。未播放时的总时长从 `src/data/project-video-metadata.json` 与扩展版本的 `videoDuration` 字段读取，本地素材通过 `ffprobe` 登记，不请求线上 MP4；工作台新增作品／版本时复用导入视频时读取到的 `session.metadata.duration`，实际开始播放后由媒体元素自身的时长覆盖显示。若控制台提示规格过期，请重新核对元数据。

手机端首次打开即显示下方 44px 的播放/暂停小按钮（位置与播放后保持一致），中央首播按钮仍保留。手机端播放开始后，直接轻点视频画面可暂停，再次轻点继续；画面触摸和底部小按钮的播放／暂停操作会在中央显示750ms 的短暂圆形图标反馈：0-150ms 淡入同时放大（78%→106%）、150-600ms 完全显示并保持 106%、600-750ms 淡出同时缩小（106%→80%），透明度与缩放关键帧严格同步：透明度与缩放分别采用 Material 风格的非对称贝塞尔曲线（进入 `cubic-bezier(0,0,.2,1)`、退出 `cubic-bezier(.4,0,1,1)`），并自动淡出（降低动态效果偏好时缩短反馈），不遮挡或截获触摸；加载中、切换版本或失败状态不得误触发二次播放。桌面仍使用浏览器原生视频控件，全屏仍遵循系统原生控制。手机端倍速使用与影院一致的居中深色薄纱玻璃横向分段胶囊（1×／1.25×／1.5×／2×，四档并排、选中项复用中性玻璃填充；直接使用 `--portfolio-glass-surface` / `--portfolio-glass-blur`，减少透明度或不支持背景模糊时降级为 `--portfolio-glass-solid`），菜单悬浮在视频下方控制栏上方并相对整条控制栏居中，不用系统白色原生选择器或遮挡画面的四行竖排菜单；支持点击外部、Esc、方向键、Home/End 和选择后恢复焦点。回归 `npm run check:cinema-controls`。

用户点击播放后，等待视频帧实际可呈现，再以 180ms 淡出播放器封面。支持减少动画偏好的浏览器直接切换。未配置播放器封面时，在同一稳定容器内完整显示原卡片封面；可能留黑，但不会拉伸。没有提前登记宽高时，显示明确的规格读取占位，再按真实元数据进入播放器，建议发布前补齐规格。

播放器封面和视频共同使用容器圆角，桌面复用 `--portfolio-content-radius`（18px），手机从同一内容圆角变量限定为 14–16px（当前 16px）。关闭时暂停并释放视频地址。


## 影院播放状态与浏览顺序

- **目录与原有箭头严格分层**：`CinemaWorkDirectory.jsx` 是同一影院 `dialog` 内的作品索引，不是第二层弹窗，更不替代 A/B/C 视频版本。主页面「作品目录」替换旧「复制链接」位置，并与分类标签在同一水平线；底部永远只有居中的上一部／计数／下一部一组箭头。**宽屏 ≥1320px、视口高 ≥601px** 按需打开右侧非模态目录并持续显示，直到 X/Escape/关闭影院；不暂停正在播放的影片，可以在目录展开期间操作播放、项目左右箭头及 A/B/C 视频版本，也可继续通过列表选片。采用两侧等宽预留，使影片中心恒定，仅在需要时等比例缩小，避免旧版右填充引起的横向偏移。更窄/更矮窗口暂时覆盖视频，底层 inert；手机 ≤760px 从底部展开，选择项目后自动收起。筛选两层 2×2（全部／精选 + 四分类）：打开时筛选与当前作品浏览范围一致（首页精选默认 8 部，分类默认该分类，不得固定选中全部 19 部）；临时浏览其他筛选但没有选新作品，不改变范围，重开时复位到当前范围。列表独立滚动，短视口保留可选的内容区。换片先解码第一版海报、失败回退封面，成功后才暂停旧视频并更新作品与浏览范围，不自动播放新视频；在作品库只 replace 当前 `?watch` 历史条目，关闭回原分类。**完全删除复制作品链接的按钮/逻辑**，但 `works.html?watch=ID` 可复制浏览器地址访问且保留原有前进/后退功能。回归 `npm run check:cinema-work-directory`、`npm run check:shareable-works`。
- **传入顺序**：首页由 `src/App.jsx` 向 `CinemaPlayer` 传入 `FEATURED_PROJECTS`，严格遵循 `project-order.json.featured` 的 8 件精选排序（手机 2×4 同时展示）；作品库由 `WorksLibrary.jsx` 传入当前筛选结果；换片不改变筛选分类，但若当前以 `?watch=ID` 展示，则替换同一历史条目的作品 ID，避免增加多条历史记录。**影院首尾不循环**，对应上一部／下一部按钮禁用；此规则不同于作品管理工作台跨分类循环导航。
- **同一作品内的版本顺序**：`src/data/project-version-order.json` 独立于作品卡片顺序，`projectVideoVersions` 使用稳定版本 ID 排序。影院首次打开默认第一条未归档视频（即使该条不是 `main`，或 `main` 已在回收站），对应的原比例海报也必须先解码；如果缺失则回退已解码的作品卡片封面。排序不会改变真实媒体元数据、主版本身份与视频 URL。
- **组件生命周期**：`CinemaPlayer` 外层 key 只区分打开／关闭，不随作品 ID 更换整个弹层；仅视频与静态海报随作品重建。调用已有 `toggleLang` 切换语言，不重建正在播放的视频、不重置进度。换片先暂停旧视频、保持旧海报或已显示视频帧，待新海报解码成功后才释放旧资源并替换画面；失败时先解码下一部的卡片封面兜底，两张都失败则保留旧画面，不再使用原本 1.5 秒的强制替换。新片暂停在 0 秒。
- **加载边界**：影院 JS/CSS 经 `lazyCinemaPlayer.js` 独立分包，首页与作品库首屏不预加载；卡片 hover、触摸、键盘聚焦时预热播放器代码及当前海报，作品库 `?watch=ID` 直达时立即预热。点击后待图片解码与播放器模块就绪再打开弹窗；失败回退当前 3:4 卡片封面。A/B 视频版本切换同样先完整解码将显示的新海报，未就绪时保留旧帧并显示轻量准备状态；视觉选中线采用克制的 Framer Motion 弹簧、文字轻上移 1px，未开始播放的海报交接用 340ms 的旧海报淡出与 8px 方向位移（新海报已预先解码，绝不黑屏；若已开始播放，禁止盖上旧海报）；快速取消、关闭或切换作品会使旧异步响应失效，8 秒超时后回退已解码的卡片封面，不能直接替换为尚未加载的图片。打开或换片时 video 保持 `paused`、`currentTime=0`、`readyState=0` 且不设置 `src`；用户明确点击播放之后才加载媒体或等待 `loadedmetadata`，不得自动请求 ImageKit。
- **带宽策略**：播放器尚未点击播放时不预请求相邻作品的原比例海报，避免在移动网络中与当前 MP4 首帧争抢下载带宽；上一部／下一部按钮在悬停或键盘聚焦时预热对应海报。MP4 的 `preload="none"` 和首帧呈现前保留海报的规则不变。
- **退出与后台**：点击关闭立即暂停并释放视频地址，焦点恢复原触发卡片；切换页面或进入后台暂停声音。**作品库播放器**的 `?watch=ID` 是独立分享状态：卡片打开创建一条 `pushState`，关闭通过浏览器 Back 返回无 `watch` 的作品库状态，Forward 可重开；首次直达分享链接也先建立站内基础历史条目。**工作台**的 `?project=ID` 仅定位卡片，与 `watch` 不相互触发。**首页精选播放器**不显示复制作品链接按钮、不改首页 URL；作品库 `?watch=ID` 可通过浏览器地址栏分享。播放器画面与控制区不应因切换语言、海报解码或短视口回流跳动。`check:shareable-works` 验证无自动播放及完整后退/前进。
- **专项检查**：`node scripts/checks/site/check-media-presentation.mjs`、`node scripts/checks/site/check-cinema-playback.mjs`、`node scripts/checks/site/check-cinema-stability.mjs`、`node scripts/checks/site/check-project-library.mjs`；`npm run check:cinema-local` 专门在本地 Vite 开发地址（默认 5174）使用真实本地 MP4，测 390/1440px、2.6 秒版本海报延迟、3.5 秒换片延迟、1.45 秒视频缓冲、404、快速取消及播放中切换，断言无真实 ImageKit 请求。此项只用于开发环境，不纳入生产预览 `check:site-full`（生产模式按配置会指向 ImageKit）。导航与弹窗见 [设计规范](./设计规范.md)。

## 自动化媒体计费保护

作品视频必须点击后才向 ImageKit 请求，保留原片传输前缀与 preload=none。自动化在浏览器导航前拦截 ImageKit 视频、缩略图及第三方收费媒体，不在 Netlify/Cloudflare/GitHub Pages 上反复加载 Hero 进行批量验收。隔离方式、收费事件响应及工作台保护以 [测试与回归维护](./测试与回归维护.md) 为唯一政策。

## Hero 原生背景视频与首帧

- 首页 `#hero-video` 是全页固定的静音背景，作品详情 `CinemaPlayer` 是独立视频播放器：只有用户主动点击播放后才给作品 MP4 设置 `src`，不能混用自动播放策略。

- 原始 `hero-mobile.mp4`（480×1040 / 24fps / 约 15.04 秒）保留为 `?heroMode=scrub` 对照版本和自动播放失败的滚动回退；运行时使用 Vite 构建后的实际指纹资源地址，不能硬编码开发路径。打开作品详情、浏览器标签隐藏时手机背景暂停，关闭详情或标签可见后恢复；尊重减少动态偏好。

- `assets/images/hero-first-frame-mobile.webp` / `hero-first-frame-desktop.webp` 是与视频分离的响应式静态首帧。当前原生 `<video>` 没有额外 `poster` 属性；替换片源需核对静帧画面。发布版不挂载旧的 `VideoPostProcess` / WebGL 后处理，不恢复 CRT、扫描线、暗角或黑边遮罩。

## 首页滚动与深链首帧稳定性

- 保留浏览器原生 `history.scrollRestoration = 'auto'`，禁止在迟到的 `load` / `pageshow` 事件强制回顶。`#projects` / `#recognition` / `#contact` 等深链由页面导航对齐到浮动导航下约 88px，真实滚轮、触摸、键盘输入优先于自动校正。
- 首页 `index.html` 初始 HTML 包含 `after-top`、`after-projects`、`outro` 三段电影穿行间隔；`heroImmersivePreview.js` 只复用，不能在 React 挂载后再插入导致整页高度跳变。三个 React 门户 `:empty` 预留适当高度供首帧锚点定位，挂载后立即由真实内容高度替代。
- 首页精选首行随 React 挂载立即请求，剩余封面进入桌面 700px／手机 520px／3G 或省流量 350px 观察器范围才挂 `src`，并立即 `loading="eager"`。正常网络下次排 normal 优先级，弱网只让首排立即请求。影院 JS/CSS 按意图预热，作品 MP4 仍只在点击播放后加载。
- 手机固定背景沿用 `100lvh`，浏览器地址栏仅改变高度时不刷新整个 GSAP，屏宽改变时再更新布局；滚动驱动原片仍可通过 `?heroMode=scrub` 手动比较。真实 iPhone Safari 的解码、功耗与地址栏体验需另外人工验收。
- 手机影院切换作品：正常高度（≥800px）时，竖幅影片无论是否有 A/B/C 版本，都为信息区保留同样的最小高度（186px），并在 `CinemaPlayer.jsx` 中统一预留影片下方控制区预算。否则单版本与多版本之间切片会使影片区域突然上下变化约 78px。短视口仍保持自然滚动，桌面各真实画幅保持现有适配。
- 回归入口：`npm run build`、`npm run check:hero-first-frame`、`npm run check:home-scroll`、`npm run check:mobile-scroll-response`、`npm run check:page-handoff`、`npm run check:cross-page-nav` 和 `npm run check:image-loading`；常规浏览器测试必须继续阻断真实 ImageKit 请求。

## 多版本播放器

原有作品与工作台新增作品都支持添加视频版本。主版本沿用既有 `project.videoUrl`、`videoWidth`、`videoHeight`、`playerPoster`；新增作品的扩展版本保存在 `auto-projects.json`，原有作品扩展版本保存在 `legacy-video-variants.json`，各自保存本地路径、线上 URL、画幅及海报。中英文版本名称独立于作品标题；右侧「作品管理」按作品统一名称→视频版本排列；单击版本标签切换，所选视频中英文名称输入框常驻显示，修改后才出现保存与撤销；保存后同步当前视频标题，且不修改上方共用作品名。标签行最右的归档图标仅处理所选视频，至少保留一条可用视频。添加视频版本的入口仍位于同一区域。版本名称由本地 `POST /api/update-version-label` 保存到相应 JSON 与修订历史，不请求 ImageKit，也不发布网站。播放器内切换先暂停旧视频、保留已显示的视频帧或海报，解码新版本海报（失败回退卡片封面）后才释放旧视频 `src`、正式更新版本；新版本仍在用户点击播放后才加载。版本按钮不创建第二条导航，也不影响作品上一部／下一部。
