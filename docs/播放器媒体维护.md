# 播放器比例与封面维护

作品卡片使用 3:4 封面；播放器独立读取 `videoWidth`、`videoHeight` 与 `playerPoster`，按实际画幅显示，不把卡片封面拉伸进播放器。静态海报按四分类目录和英文 MP4 文件名存放；原有主版本元数据由 `src/data/project-video-metadata.json` 维护。新增作品的附加版本在 `src/data/auto-projects.json` 的 `variants[]`，原有作品追加版本在 `src/data/legacy-video-variants.json`。

## 选帧与媒体目录

- **新增作品**：使用 `npm run covers`，导入视频并人工选择时间点。同一选帧分别导出 900×1200 的 3:4 卡片封面和按真实显示比例（包括 SAR）生成的播放器原比例海报。
- **追加版本**：原有作品和工作台新增作品均可添加 MP4 版本及独立播放器海报，主视频／主海报不被覆盖；版本间可采用不同画幅，单作品最多 8 个版本。
- **仅更换卡片封面**：原位更新 `assets/images/project-covers/<category>/<English Title>.webp`，不会修改播放器海报或其选帧时间；上一版进入 `.cover-studio/project-revisions/cover-history/`。
- **修改英文标题**：工作台同时同步本地 MP4、卡片封面和播放器海报的文件名及 JSON 引用；原始上传素材和 ImageKit 地址不改。
- **播放器海报目录**：`assets/images/player-posters/<category>/<MP4 English Stem>.webp`，与每个 MP4 版本一一对应。四分类为 `commercial`、`short-film`、`social`、`visual`。

**独立更换原比例海报**：工作台「更换作品封面 → 播放器海报 · 原比例」可选择任意作品及主版本／A/B 视频版本，从该版本本地 MP4 选帧或导入画幅一致的图片，比较旧海报后单独替换。原图备份、比例校验与选帧时间同步由工作台管理；运行 `npm run check:cover-poster`。旧的 `scripts/generate-player-media.mjs` 仍输出“中文作品名＋哈希”，未适配四分类目录，**不要在现行作品库运行该脚本**。

## 播放器行为

弹窗在显示前使用预生成的宽高计算尺寸。`loadedmetadata` 用于核对；已有元数据不在播放时改变比例。若控制台提示规格过期，请重新运行生成脚本。

用户点击播放后，等待视频帧实际可呈现，再以 180ms 淡出播放器封面。支持减少动画偏好的浏览器直接切换。未配置播放器封面时，在同一稳定容器内完整显示原卡片封面；可能留黑，但不会拉伸。没有提前登记宽高时，显示明确的规格读取占位，再按真实元数据进入播放器，建议发布前补齐规格。

播放器封面和视频共同使用容器圆角，桌面复用 `--portfolio-content-radius`（18px），手机从同一内容圆角变量限定为 14–16px（当前 16px）。关闭时暂停并释放视频地址。


## 影院播放状态与浏览顺序

- **传入顺序**：首页由 `src/App.jsx` 向 `CinemaPlayer` 传入 `FEATURED_PROJECTS`，严格遵循 `project-order.json.featured` 的 8 件精选排序（手机 4+4）；作品库由 `WorksLibrary.jsx` 传入当前可见筛选结果，换片不改变筛选类别或 URL。**影院首尾不循环**，对应上一部／下一部按钮禁用；此规则不同于本地工作台跨分类循环导航。
- **组件生命周期**：`CinemaPlayer` 外层 key 只区分打开／关闭，不随作品 ID 更换整个弹层；仅视频与静态海报随作品重建。调用已有 `toggleLang` 切换语言，不重建正在播放的视频、不重置进度。换片先暂停旧视频、准备新海报再释放旧资源，新片暂停在 0 秒。
- **加载边界**：从作品卡片 hover、触摸或键盘聚焦时仅预热独立播放器海报，点击后待图片解码再打开弹窗；失败回退当前 3:4 卡片封面。打开或换片时 video 保持 `paused`、`currentTime=0`、`readyState=0` 且不设置 `src`；用户明确点击播放之后才加载媒体或等待 `loadedmetadata`，不得自动请求 ImageKit。
- **退出与后台**：点击关闭立即暂停并释放视频地址，焦点恢复原触发卡片；切换页面或进入后台暂停声音。关闭与浏览器原有 `popstate` 不额外增加历史记录。播放器画面与控制区不应因切换语言、海报解码或短视口回流跳动。
- **专项检查**：`node scripts/check-media-presentation.mjs`、`node scripts/check-cinema-playback.mjs`、`node scripts/check-cinema-stability.mjs`、`node scripts/check-project-library.mjs`；导航与弹窗见 [设计规范](./设计规范.md)。

## 自动化测试不消耗 ImageKit 流量

Playwright 入口统一使用 `scripts/lib/safe-media.mjs` 的 `createSafePage` / `createSafeContext`。这两者在打开页面前拦截所有 ImageKit 域名请求：对 MP4 返回 `scripts/fixtures/` 内 12 秒的本地横屏/竖屏测试视频，非 MP4 请求阻断；不会下载远程视频，也不会产生 CDN 带宽或 VPU 消耗。

可运行 `node scripts/check-safe-media-guard.mjs` 来确认本地媒体实际能播放并且访问被拦截。所有常规回归测试均应使用这些保护函数。若未来必须验证 ImageKit 在线播放，先获得用户明确授权，进行一次性人工检查，不要为常规测试打开自动化真实 CDN 访问。

该保护只存在于 `scripts/` 中，不影响真实网站运行或正式部署。

**手动本地预览**：`npm run dev` 时播放器优先指向 `assets/videos/works/` 内的 18 部作品、21 条本地视频；不会调用 ImageKit。正式 `npm run build` / Netlify 部署则保留各版本配置的 ImageKit 原片 URL。开发者若缺少本地 MP4，应补齐本地文件，不允许自动回退到远程 CDN。

## Hero 移动端首帧与加载兜底

- `assets/images/hero-first-frame-mobile.webp`（640×360）和 `assets/images/hero-first-frame-desktop.webp`（1280×720）直接从当前 Hero 原片约 0.4 秒位置截取；更换 `assets/videos/hero/hero-mobile.mp4` 或 `hero.mp4` 时，同步重新生成这两张静态海报，以免加载切换时画面跳动。
- `index.html` 在 `#video-bg` 设置响应式背景首帧，`#hero-video` 另有原生 `poster`。移动端在首次打开时立即 `warmVideo()`，不再依赖触摸或滚动事件才获取视频首帧；桌面端保留延迟预热，降低无谓下载。
- `VideoPostProcess.jsx` 只在真实视频帧解码并完成第一次 WebGL 渲染后添加 `is-webgl-ready`，避免黑色画布遮挡原生视频；WebGL 不可用时仍回退到原生视频及海报。不改变作品视频的 ImageKit 配置。
- 运行 `npm run check:hero-first-frame`（拦截本地 Hero MP4 模拟视频加载失败，并检查正常解码与 WebGL）；同时运行 `npm run check:clipboard` 确保剪贴板权限拒绝时不会误报复制成功。真实 iOS Safari 仍需用手机实测一次。

## 手机端滚动跟手与背景稳定性（2026-10-26）

- 首页滚动叙事仍为 15 秒；桌面保持原来 1280×720 / 30fps 的 `hero.mp4`、滚动定位逻辑和 60fps WebGL。
- 手机 `hero-mobile.mp4` 使用 640×360 / 30fps H.264，9 帧（约 0.3 秒）一关键帧、无 B 帧、faststart；约 2.9MB，原版 1 秒 GOP 文件本地备份在 `.audit/mobile-scroll-investigation-20261026/`。更换素材时必须保留适合滚动定位的关键帧密度。
- `index.html` 手机端 seek 上限约 20 次/秒，当前定位未完成不再次打断，停手后纠正到真实滚动时间；手机固定背景使用 `100lvh`，窗口只有高度变化时不刷新 GSAP，宽度变化（旋转）仍刷新。
- `VideoPostProcess.jsx` 手机滚动 WebGL 上限 30fps、静止 20fps；桌面行为不变。
- `npm run check:mobile-scroll-response` 检查 390/430/1440px 的 seek、进度、resize、触控视口与媒体安全。**真实 iOS Safari 的地址栏及跟手感仍需用手机验收**。

## 手机端 WebGL 图形上下文恢复

`VideoPostProcess.jsx` 在 `webglcontextlost` 时阻止失效画布遮挡背景，取消旧帧循环，立即恢复原生视频层（视频自身含 `poster`，父层含静态首帧）；在 `webglcontextrestored` 后重新构建 OGL renderer / texture / shader 并确认完成新帧绘制后再显示 WebGL。上下文始终无法恢复时，继续保持原生视频/海报兜底。不得通过重新请求 ImageKit 视频来恢复 GPU。

运行 `npm run check:webgl-recovery` 在手机 390px 与桌面 1440px 模拟 GPU context loss + restore，检查兜底、恢复和资源地址不变。真实 iPhone Safari 仍需要人工验证。

## 多版本播放器

原有作品与工作台新增作品都支持添加视频版本。主版本沿用既有 `project.videoUrl`、`videoWidth`、`videoHeight`、`playerPoster`；新增作品的扩展版本保存在 `auto-projects.json`，原有作品扩展版本保存在 `legacy-video-variants.json`，各自保存本地路径、线上 URL、画幅及海报。中英文版本名称独立于作品标题；右侧「视频版本」任务区单击版本标签切换视频；点击标签旁铅笔或「重命名当前版本」编辑中英文标签，保存后同步当前版本标题。添加入口位于右侧「视频版本」区。版本名称由本地 `POST /api/update-version-label` 保存到相应 JSON 与修订历史，不请求 ImageKit，也不发布网站。播放器内切换会立即暂停并释放旧的视频 `src`，新版本仍在用户点击播放后才加载。版本按钮不创建第二条导航，也不影响作品上一部／下一部。
