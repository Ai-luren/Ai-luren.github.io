# 个人作品集设计规范

本文是本项目唯一持续生效的视觉与交互规范，记录当前生产构建中已落地的规则，作为后续新增组件的复用依据。它描述实际生效的页面，不要求把语义不同的页面强行做成同一外观。Token 真值位于 `src/styles/apple-system.css` 与 `src/styles/card-surfaces.css`；组件排版和响应式变体由对应组件样式负责。日期化验收和审计文件只保留历史测试结果或建议，不覆盖本文与当前源码。

## 设计方向

作品和影像优先，界面采用中性深色、清晰层级与克制动效。首页的 Hero 与滚动视频保留独立的叙事样式；内容区以可读性和一致的媒体边界为主。不同页面在筛选控件、导航形态和浏览行为上可以保留符合用途的差异；首页精选与全部作品使用同一作品卡媒体比例和信息节奏。

## 字体与文字层级

字体栈由 `--font-display`、`--font-body` 和 `--font-mono` 提供：系统无衬线字体用于标题与正文，等宽字体用于编号、标签和技术性元信息。

| 语义角色 | 实际规则 |
|---|---|
| Hero 标题 | 独立展示层级，最终规则在 `index.html` / `apple-system.css`；使用响应式 clamp、紧凑行高和自然换行。`--type-hero` 是兼容 Token，具体 Hero 规则仍由专属选择器控制。 |
| 页面 H1 | `.page-title` 消费 `--page-title-size/weight/line-height/letter-spacing`。桌面最大 64px；作品库 390px 手机端 computed 为 39px。独立页面标题不附加章节蓝线。 |
| 首页章节 H2 | `.section-title` 消费 `--section-title-*`。1440px 为 64px/1.02，1024px 为约 49.15px/1.02，390px 为 39px/1.02。 |
| 专业实力的四个同级子标题 | 获奖、平台、自媒体与 AI Lab 使用同一字号 Token：1440px 为 43.2px、1024px 为 36px、390px 为 31.2px。均严格小于一级「专业实力」标题；手机端 AI 平台创作者卡片的内部 H3 进一步降为 24–28px。 |
| 项目卡片标题 | `--project-card-title-*`：桌面 16px、600、1.4；手机 14px、500、1.45。首页和作品库共享。 |
| 正文 | 通用正文基准 `--type-body: 14px`；模块可以按阅读场景设置局部字号与行高。关于我正文桌面约 16–17px、行高 1.72，手机 16px、行高 1.75。 |
| 辅助说明 | `--apple-secondary` 为主要辅助色；项目说明使用 `--project-card-detail-*`，12px、400、1.55。更弱元信息使用 `--apple-tertiary`。 |

中英文共用同一语义 Token。英文标题、项目名称和正文自然换行；项目卡片允许 `overflow-wrap:anywhere`，奖项说明可换行，不以缩小字体或强制单行解决长度。中文保持自然断行。标签和按钮避免超出容器；英文菜单标签按导航可用宽度布局。

## 线条的语义

- **章节标题装饰线**：首页章节和影响力子章节下方的蓝色短线已移除，不用其他线条替代。页面 H1 同样不附加装饰线。`--apple-blue` 仍可用于主操作、键盘焦点及有语义的作品说明标记；不要把这些功能色误当成章节装饰。
- **作品说明竖线**：项目卡片 `.comet-archive__details::before` 与作品播放器详情 `.cinema-player__caption p::before` 共享 `--project-card-marker-*` 和 `--project-card-detail-gap`：蓝线 2×14px、左侧与标题齐平、第一行文字盒子上沿下移 2px、文字向右缩进 12px（2px 线＋10px 间距）。桌面、手机及中英文遵循相同规则；多行说明的蓝线不随文本增高或纵向居中到整个段落。它标示奖项或分类说明，与章节装饰线无关。
- **选中状态线**：导航和筛选器自身状态。桌面主导航用文字下方的 1px 中性白线；移动作品分类 Tab 用当前文字色的 1px 短线。移动导航的当前项使用既有白色圆点。它们表示当前选择，不使用章节蓝线。

## 圆角与媒体比例

共享圆角由 `src/styles/card-surfaces.css` 定义：

| Token | 值 | 语义 |
|---|---:|---|
| `--portfolio-panel-radius` | 24px | 大面板、桌面玻璃卡片、导航胶囊。 |
| `--portfolio-content-radius` | 18px | 作品封面、内容媒体、桌面视频画面、获奖图片查看器中的原图。 |
| `--portfolio-tile-radius` | 12px | 紧凑重复 tile。 |
| `--portfolio-control-radius` | 999px | 胶囊操作控件。 |
| `--portfolio-icon-radius` | 50% | 圆形图标按钮、头像。 |

特殊上下文保留组件规则：播放器手机画面圆角为 16px；关于我与合作联系玻璃卡片手机端为 20px；移动作品分类 Tab 无圆角。不要把上述语义强制改成同一个值。

奖项画廊缩略图是紧凑媒体 tile，使用 12px `--portfolio-tile-radius`；打开查看器后展示原比例图片，桌面使用 18px 内容圆角，手机限于 14–16px。不要将缩略图规则套到查看器原图上。

封面比例契约：

- 首页精选和 `works.html`：全部尺寸统一使用 `--portfolio-work-cover-ratio: 3 / 4`，原始作品封面保持既有 `cover / contain` 规则。
- 两处作品卡都消费 `--portfolio-work-title-gap`（桌面 10px、手机 8px）和 `--portfolio-work-caption-gap`（桌面 5px、手机 4px）；手机作品卡以 720px 为断点。
- 媒体边框、18px 圆角、阴影与标题／奖项字号共享；首页的背景视频与手机分页、作品库的黑色画廊和筛选是有意保留的布局差异。
- 首页与作品库作品封面底色统一使用 `--portfolio-content-surface`；使用 contain 显示的边缘不能出现跨页面色差。桌面、手机和中英文均只在封面右下角常驻一处「播放／Play」（不可播放时为「待上传／Pending upload」）深色胶囊，标题和蓝线说明位于封面下方，不增加第二个点击热区。两页统一使用 `CinemaPlayer` 打开作品，默认不自动请求视频流。
- 获奖图片查看器按原图自然比例约束视口，不套用视频作品的 3:4 卡片比例。
- 图片保持完整内容；需填充时必须遵循组件现有的媒体处理规则，不擅自改变数据或裁切意图。

## 面板、玻璃与阴影

共享表面 Token：

- 面板：`--portfolio-panel-surface: rgba(28,28,30,.72)`、`--portfolio-panel-border: rgba(255,255,255,.14)`、`--portfolio-panel-blur: blur(22px) saturate(1.08)`、`--portfolio-panel-shadow`。
- 内容媒体：`--portfolio-content-surface: rgba(0,0,0,.58)`、`--portfolio-content-border: rgba(255,255,255,.18)`、`--portfolio-content-shadow`；媒体本身不叠第二层模糊。
- 紧凑 tile：`--portfolio-tile-surface: rgba(255,255,255,.05)`、`--portfolio-tile-border: rgba(255,255,255,.09)`；Hover 表面为 `--portfolio-tile-surface-hover`。
- 弹层遮罩：`--portfolio-modal-surface: rgba(12,12,13,.9)`、`--portfolio-modal-blur: blur(28px) saturate(1.02)`；降级使用 `--portfolio-modal-solid`。

面板只使用一层材质，不重复嵌套玻璃。**Cinematic Content Glass** 是信息面板的唯一共享材质：`--portfolio-glass-surface: rgba(26,27,31,.82)`、`--portfolio-glass-blur: blur(22px) saturate(1.04)`。适用于三块影响力面板（获奖、平台超创、自媒体）、实验室索引、关于我／合作联系、Hero 证明卡及移动作品容器，由 `src/styles/card-surfaces.css` 将角色绑定至对应选择器。**Chrome Glass**（导航胶囊）继续使用较轻的 `--portfolio-panel-surface: rgba(28,28,30,.72)` 和 `--portfolio-panel-blur`；**Modal Scrim**（菜单／播放器／账号资料遮罩）继续使用更深的 `--portfolio-modal-surface: rgba(12,12,13,.9)` 与 28px 模糊，账号资料与获奖弹层的内容区域保持透明（不叠第二层玻璃），需要不透明卡片时才使用 `--portfolio-modal-panel-surface: #191a1e`。背景材质以 Token 为准，`index.html` 不应对阅读面板新增实色或禁用模糊的强制覆盖。边框、阴影、面板圆角仍统一复用 `--portfolio-card-*`，Hero 证明卡沿用 18px 内容圆角；封面、截图、视频本体不叠加第二层模糊。

`prefers-reduced-transparency: reduce` 与不支持 `backdrop-filter` 时采用不透明中性深色背景并关闭模糊；不以 `prefers-reduced-motion` 代替透明度降级。材质降级也分三种语义：Chrome Glass 使用 `--portfolio-panel-solid`，Cinematic Content Glass 使用 `--portfolio-glass-solid`（目前都为 `#1c1c1e`），仅全屏遮罩使用 `--portfolio-modal-solid`（`#0c0c0d`）。正常模式的原有透明度、模糊、阴影和圆角保持不变。所有主要阅读面板的无模糊降级统一在 `src/styles/card-surfaces.css` 声明；导航及获奖查看器的降级由 `src/styles/navigation.css` 控制，账号资料遮罩沿用自身查看器降级。不得把导航使用的材质错误地替换成全屏遮罩色。清理材质规则时只删除确认不再有 DOM 消费者的历史选择器，不调整播放器、媒体截图等内容表面。

生产构建的 `vite.config.js` 当前禁用 CSS minify：默认压缩器会移除 Edge 所需的无前缀 `backdrop-filter`。调整压缩策略前必须核对 `dist/assets/*.css` 和 Edge 中的 computed style。

## 弹窗动效契约（Step 01）

作品播放器、获奖荣誉、AI 自媒体账号资料使用同一进入／退出节奏：`--apple-duration-modal: 260ms`、`--apple-duration-modal-exit: 220ms`、`--apple-ease` 缓动，内容区有 8px 以内的轻微位移。仅透明度和内容 transform 参与过渡；共享玻璃导航不能缩放/位移，Backdrop 的模糊半径和媒体布局不参与动画。退出前保留模态层，动画后再卸载并恢复源触发器焦点、滚动和 inert 状态；原生影片退出时立即停止媒体，不允许等待动画结束才停止播放。连续点击关闭只执行一次，动画未完成时允许关闭，`prefers-reduced-motion: reduce` 时直接关闭。运行 `npm run check:modal-motion` 验证手机/平板/桌面、正常/减少动态效果及零 ImageKit 流量。

## 按钮、链接与交互状态

按语义保留控件差异：主行动按钮、文字链接、胶囊筛选、圆形图标按钮和箭头不是同一种外观。导航在 761px 起统一显示四项横向文字栏目（含平板竖屏）；760px 及以下使用折叠菜单。首页与全部作品页共用同一玻璃胶囊导航及语言切换控件。 跨越 760/761px 断点时，正在打开的手机菜单必须立即关闭并释放滚动锁定/背景 inert；菜单作为模态层，Tab 不得跳出弹窗，关闭后聚焦有效入口。作品库桌面筛选为胶囊，手机端为文字 Tab。

- 默认态使用对应语义表面、描边和主次文字色。
- Hover 提升文字/表面/描边对比；动效使用 `--apple-duration-control: 180ms` 和 `--apple-ease: cubic-bezier(.22,1,.36,1)`。
- `:focus-visible` 使用 2px `--apple-blue` 外框并留出 offset；不可移除键盘焦点。
- Active/Pressed 使用略高对比的控件表面。禁用箭头降低不透明度且不可操作。
- 触控按钮最小热区通常为 44×44px；尺寸较小的图形由热区容器承载。
- Floating Dock 固定图标占位容器，图标与提示以悬浮/transform 反馈显示，不能改变外层玻璃卡片尺寸；触屏不依赖 Hover。

## 统一导航的不可破坏原则

首页和全部作品页的一级导航固定为四项：**精选作品｜全部作品｜专业实力｜联系**（英文为 Featured｜All Work｜Expertise｜Contact）。「专业实力」聚合获奖荣誉、平台超创、自媒体和 AI Lab（技术实践）四个子模块；AI Lab 保留原锚点和项目链接，只降为子章节，不另建一级导航或 Hover 下拉。四项入口在桌面导航、首页手机菜单、作品库菜单中统一。旧的奖项/平台/自媒体/Lab 深链接保持有效；对应区域滚动时都选中「专业实力」，联系方式/关于我区域选中「联系」，全局同时只能有一个当前项下划线。选中状态由页面滚动监听统一管理，不应在 React 组件中另写平行的滚动监听。用户点击一级导航触发平滑滚动时，目的地选中线一直保持至本次滚动结束；途经中间章节的 IntersectionObserver 仍可更新背景，但不能抢走导航选中状态。用户滚轮、触摸或滚动键主动中断时解除临时锁定，并恢复正常滚动高亮。

**全站只有一套导航视觉与交互契约。** 首页主导航、作品库导航、AI 获奖图片查看器、作品详情播放器和 AI 自媒体账号资料查看器，都使用共享的导航胶囊样式。任何新弹窗或详情查看器应当直接复用 `src/components/CinemaNavigation.jsx`；不得在弹窗内另造标题栏、语言切换按钮、关闭按钮、返回胶囊或相似但不相同的导航组件。

- 弹窗只显示 **一条**共享导航：头像与品牌、语言切换和标准关闭按钮。原页面导航应隐藏，背景不可聚焦。
- 模态边界必须覆盖共享导航与内容本体。原生 `dialog.showModal()` 使用浏览器模态语义；自定义获奖与自媒体查看器在最外层设置 `role="dialog"`、`aria-modal="true"` 和标题关联 `aria-labelledby`，内部内容容器不能另设第二个对话框；视觉容器的 `role="presentation"` 不可替代模态语义。
- 弹窗内容（例如「小红书」、奖项标题、作品名称）属于内容区，不能伪装成第二条导航。查看器的关闭按钮、语言状态、焦点管理、Esc 关闭与返回触发点的逻辑必须回归验证。
- 新增查看器时，先检索 `CinemaNavigation`、`src/styles/navigation.css` 以及既有查看器实现，**复用而非复制**。除非统一修改共享导航本身，否则禁止新增 `*-dialog-header` / 私有关闭按钮来替代导航。
- 键盘焦点下，获奖卡片、自媒体账号资料和保存二维码复用蓝色 `--apple-blue` 焦点环；鼠标 Hover 仍沿用组件反馈。关闭弹窗后焦点返回触发元素，背景从 inert 恢复。作品播放器、获奖查看器、账号资料及作品库折叠菜单均要满足 Esc 关闭、Tab 不逸出。减少动态效果时允许显示更高对比度的焦点轮廓。
- AI 自媒体手机端保持抖音主记录在上、其余三条按顺序紧凑排列；所有记录的动作顺序统一为「查看账号资料」再「访问主页」（对没有主页链接的视频号只显示前者），不允许因作品模块改动而回退。
- 每次修改全局 Token、影响力模块、作品卡或导航，必须运行 `npm run check:social-media` 与相关的作品、导航回归测试，不得只检查改动模块。

## 布局与响应式策略

- 内容版心最大约 1220px；平板以可用宽度和安全边距收缩，手机主内容左右各约 16px。导航胶囊有独立的居中宽度约束，不改变正文版心。
- 首页精选桌面四列；手机双列且每页四项。作品库桌面随宽度采用两、三、四列，手机双列。两页共用封面→标题→奖项／分类说明的阅读顺序。手机作品库的 5 个分类 Tab 保证至少 44×44px 的实际触控热区，320px 等窄屏允许自然排成两行。
- AI 获奖荣誉、AI 平台超创和 AI 自媒体共用章节外层节奏：各自标题与说明在上，整宽玻璃面板在下；桌面与手机均保持这一顺序，版心内的标题到面板间距由共享影响力间距 Token 控制。三个面板内部仍按内容用途分别使用奖项轮播、平台展示和自媒体 1+3 信息布局。
- AI 平台超创的 8 个品牌 Logo 和创作者身份是**静态展示**：在一层 Cinematic Content Glass 内以桌面 4×2、手机 2×4 的细分隔网格组织，不再为每个平台添加独立玻璃卡片边框、阴影或点按缩放。AI 自媒体仍然是抖音主账号与三个次级账号；≥900px 时将主账号的数据与操作组合在右侧三条记录的高度范围内垂直居中，≤899px 维持现有响应式排版。
- AI 获奖荣誉画廊采用横向滚动和既有箭头：721–1023px 每屏 2 张，1024–1279px 每屏 3 张，1280px 及以上每屏 4 张；720px 及以下只渲染当前一张主卡，并用箭头、分页点和横向手势切换，不露出下一张。轮播按实际裁切后的可视宽度分页，末页必要时与前页重叠一张，以保证卡片完整。
- 获奖画廊的证据包含赛事奖项、入围与公开展映，统一以「荣誉与展映 / AWARDS & SHOWCASES」概括，不把展映照片标注成获奖证书。中英文顶部辅助标签均为 11px。≤389px 时分页按钮维持 24×44px 点击区域、箭头维持 44×44px，并与分页区互不重叠；390–720px 分页按钮沿用 28×44px。运行 `npm run check:award-pagination`。
- 奖项图片使用 `object-fit: contain`，不裁切；图片、标题和说明在同一内容列中左边缘对齐。桌面说明区自然随内容高度，标题 14px/600、行高 1.3，说明 11px/400、行高 1.4，标题与说明间距 4px；长英文自然换行，不预留空白行、不截断。桌面玻璃容器上下 padding 为 24px/20px，简介与画廊间距为 8px。Hover/Focus 反馈不得通过缩放或位移改变卡片几何尺寸。
- AI 实验室作为「专业实力」中的次级内容区，标题字号低于一级「专业实力」，沿用编辑式列表结构与独立 #experiments 锚点，不统一成图片卡片。
- 四个同级子标题的左边缘统一与「专业实力」主标题对齐，不允许在平板和桌面给获奖、平台、自媒体三个标题额外添加 4px 左内边距。
- 四个子标题到对应玻璃卡片的距离统一使用 `--expertise-title-panel-gap`：<=760px 为 20px，>=761px 为 28px。由 `--expertise-subheading-size` 表达共同的子标题语义；卡片内 H3 使用更低的 `--expertise-card-heading-size`（仅手机端）。实验室不再叠加列表 margin-top 与标题默认 margin-bottom。一级标题到第一子标题使用 `--expertise-main-subheading-gap`（手机 36px，桌面 44px）。
- 关于我与合作联系使用一体式玻璃卡：桌面约 60:40 双栏，联系方式与简介处于同一主信息区，底部细分隔线后排列社交 Dock；手机上下堆叠，再展示社交入口。卡片后方的页脚只保留品牌与版权信息。
- 小高度弹层内容允许内部滚动，顶部导航和关闭操作需保持可访问；视频按真实画幅 contain 展示。

## Hero 发布效果一致性

正式首页固定使用当前已验收的 Hero 蒙版和 WebGL 色彩/CRT 默认参数。旧的 `ailuren-video-tuning-v18`、`ailuren-hero-mask-v2` 浏览器 localStorage 值不可影响正式页面；发布版不提供后台调参面板。调整默认效果必须通过代码和视觉回归审核，不得在浏览器里临时保存并使其影响真实访客。

## 组件新增与维护入口

- 页面/全局字体、颜色、标题语义和动效：`src/styles/apple-system.css`。
- 面板、内容媒体、tile、模糊、边框、阴影及圆角：`src/styles/card-surfaces.css`。
- 主导航布局和状态：`src/styles/navigation.css`。
- 首页与作品库共用卡片结构及文字/竖线基础规则：`src/components/ProjectCard.jsx`、`src/components/ProjectCard.css`；作品库页面布局变体在 `src/components/WorksLibrary.css`。
- 获奖、平台和自媒体：`src/components/ImpactEvidence.jsx`、`src/components/ImpactEvidence.css`。
- 首页静态章节、Hero 和关于我/合作联系结构：`index.html`；新增独立动态模块时使用对应 React 组件，不在此处另建重复 Token。

添加样式前先检查上述 Token 的实际生产计算值和当前断点覆盖；只有语义确实缺失时才新增 Token。保持首页与作品库的合理差异，不以“统一”为由引入全局覆盖或大量 `!important`。

维护时优先使用各层负责文件：Hero 内容与滚动背景在 `index.html`，共享字号与语义 Token 在 `apple-system.css`，材质角色在 `card-surfaces.css`，共享导航几何在 `navigation.css`，作品库局部布局在 `WorksLibrary.css`。不要恢复已被同条件、同选择器后续声明覆盖的旧声明，也不要把特定页面的差异当成全局 Token 冲突。

玻璃材质补充验证由 `npm run check:glass-material` 覆盖 360/390/760/1024/1440px × 中英文 × 正常、降低透明度和模拟不支持模糊三种模式；模拟不支持仅用于验证现有 CSS @supports 分支，不等于旧浏览器或 Safari 实机认证。

设计系统基础契约由 `npm run check:design-system` 验证：横跨首页与全部作品页，对 360/390/760/1024/1440px × 中英文检查单导航、面板玻璃、作品封面比例与圆角、标题层级和横向溢出。该脚本只检验已验收的基础材质，不取代视觉走查、图片加载验证、模态框交互与移动端手势测试。

本项目当前没有 `npm run check` 脚本；按改动范围运行 `scripts/check-*.mjs` 中适用的导航、播放器、移动手势和材料降级检查，并记录脚本的过时断言，不通过删测试掩盖失败。
