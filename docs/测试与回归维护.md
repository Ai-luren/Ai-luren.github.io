# 测试与回归维护

这份文档是测试入口、覆盖关系及安全边界的统一说明。视觉规范仍以 [设计规范](./设计规范.md) 为准；不要为优化测试数量而删除断言或放松页面要求。

## 如何选择测试

| 使用场景 | 命令 | 覆盖与约束 |
| --- | --- | --- |
| 修改脚本、整理目录后先核对计划 | `npm run check:plan` | **只读**：校验测试模块归属、重复执行、命令引用及间接覆盖；不启动浏览器或服务 |
| 日常网站修改 | `npm run check:smoke` | 15 个入口：构建、项目结构、封面/排序、手机菜单、CSS、媒体安全和播放器 |
| 日常工作台修改 | `npm run check:workbench-core` | 11 个入口：会话、工作区、历史、保存、版本、排序及回收站的隔离回归 |
| 日常完整核对 | `npm run check:project` | 上述两个快速集合串行，26 个入口；**不是全部深度测试** |
| 发布前网站深测 | `npm run check:site-full` | 67 个入口，在独立本机生产预览上执行；包括多屏宽与高级交互 |
| 发布前工作台深测 | `npm run check:workbench-full` | 31 个入口，含隔离副本的写操作及当前 5190 服务的只读验收 |
| 发布前全部深测 | `npm run check:adversarial` | 先网站后工作台，98 个入口；不要与前两项重复串行运行 |
| 本地 MP4 防黑屏、真实缓冲 | `npm run check:cinema-local` | **专项**：需要本地 Vite 开发服务器（默认 5174），不适合生产预览 |
| 专项动效与预加载 | `npm run check:motion-polish` | 组合五个维护中的子测试：弹窗进出、筛选稳定、跨页预热、Hero 首帧/标题、章节与卡片单次入场 |

**测试入口数量不等于独立测试文件数量。** 当前 109 个测试模块均在维护清单中：网站 75、工作台 34（以 `check:plan` 实际输出为准）。部分 npm 入口一次调用多个子文件。快速与深度集合在功能上有重叠，这是分层验证的预期；同一次深度集合内部不重复执行同一测试文件。

## 唯一入口与兼容规则

- `scripts/lib/check-suite-catalog.mjs` 是快速测试和深度测试队列的**唯一归属清单**；`scripts/run-check-suite.mjs` 与 `scripts/run-adversarial-checks.mjs` 使用同一份定义。
- `scripts/checks/site/check-test-plan.mjs` 实现只读的覆盖检查；`npm run check:plan -- --json` 可查看有序队列。新增测试时必须保证其存在已登记的 npm 命令、深度直调列表、经验证的组合测试入口或独立专项入口。
- `check:workbench-import-ui` 保留为独立排错命令，但工作台深测不再单独执行：组合入口 `check:workbench-create` 已包含同一文件 `check-cover-studio-import-ui.mjs`。避免双跑，**并未删测试**。
- `check:motion-polish` 会调用 5 个动效测试；普通标题与卡片仅首次入场的现行专项为 `check:editorial-motion`（`check-editorial-once-motion.mjs`），已包含在组合测试中，深测不重复单独运行。
- **影院目录专项**：`npm run check:cinema-work-directory` 检查 320–1440px × 双语、目录入口在分类标题右侧、底部只有一对作品箭头、6 类筛选全部可见、海报不自动播放、A/B/C 与跨分类独立、`?watch` 历史无额外条目、播放器内无复制链接 UI、宽屏目录不锁播放/切片且开关不引起画面水平位移；`npm run check:shareable-works` 对分享/复制和浏览器前进后退守护。
- **首页导航专项**：修改选中态、锚点、Hero 滚动或 ScrollTrigger 时，先 `npm run build`，再启动本地**生产预览**并设置 `PORTFOLIO_URL`，运行 `node scripts/checks/site/check-desktop-primary-navigation.mjs`、`npm run check:nav-scroll`、`npm run check:home-scroll`。不仅验证导航下划线，还要确认首次点击「专业实力」确实滚到目标区域、用户主动滚动可解除锁定；开发服务器通过不代表生产构建通过。
- **影院按需加载专项**：`App.jsx` 与 `WorksLibrary.jsx` 通过 `lazyCinemaPlayer.js` 动态加载影院。首次进入首页／作品库不应请求 `CinemaPlayer-*.js/.css`；卡片 hover／触摸／聚焦预热，点击可打开/关闭，作品库 `?watch=ID` 直达可打开。点击播放前视频必须无 `src`，测试禁止请求 ImageKit。回归 `check:image-loading`、`check:shareable-works`、`check:cinema-work-directory`；线上 Deploy Preview 只做有限且拦截视频的冒烟，避免反复下载 Hero。
- 对**仍有效**的专项入口保持兼容；只有在现行覆盖中完整迁移独有断言、确认没有调用方、通过 `check:plan` 与主专项后，才能删除无独立价值的历史测试和 npm 别名。现在分别由 `check:proof-viewer-polish` 验证放大/拖拽/切图/Escape，由 `check:award-pagination` 验证获奖放大提示，由 `check:shared-mobile-menu` 验证遮罩提前显现；不保留第二套重复检查，也不得为通过率删除独有断言。
- 日常对指定模块只运行其专项测试与 `check:project`，发布前再选对应深测；不要每次修改文字都运行所有测试。

## 安全边界

- **零第三方媒体计费**：网站自动化、截图、网络审计、性能测试与部署预览（正式站和 Netlify Deploy Preview）全部必须对 `*.imagekit.io` 域名断网，覆盖 `http/https`、MP4/WebM、缩略图、无扩展名与带 `?updatedAt` 的原文件地址。既要防带宽，也要防首次优化、VP9/WebM 转码及 `get thumbnail` 消耗 VPU；不得以 Forever Free 每月 500 VPU 上限代替安全防护。
- **临时 Playwright 脚本同样强制**：只有在 browser context 导航前安装了覆盖全部 ImageKit 网络请求的拦截，才可访问外部部署页面；仓库内脚本复用 `scripts/lib/safe-media.mjs`，临时脚本（`node_modules/.cache`、`/tmp` 等）须复用或实现同等严格且经核验的拦截。禁止裸页面、`route.continue()`、只检测媒体扩展名或只拦截 `resourceType=media`；不要通过访问线上 CDN 来测试拦截是否有效，应使用本地模拟和检查脚本静态逻辑。真实线上媒体单次核验需要用户明确批准。
- **后台排查策略**：`Media Library` 视频列表、`Media use analysis`、视频详情/播放器不是安全的零成本只读入口；禁止以无人值守浏览器自动化批量访问、滚动、截图、刷新这些页面。需要查流量/VPU 时，优先调用已授权且明确只读的 ImageKit Admin MCP usage 接口（不能调用转码、缩略图、删除、清缓存或修改配置）；OAuth 不可用、接口不支持时，**停止自动访问**，使用用户提供的截图/导出明细或寻求 ImageKit Support，不得回退为批量浏览 Dashboard。只有明确获批、确认能够拦截所有媒体 CDN 请求时才可单次访问后台非媒体数据页，自动打开的请求仍须审计。
- 工作台有写入能力的测试只能在临时隔离项目运行；禁止改正式作品、封面、视频、排序和版本记录。
- `check:workbench-live` 检查**已经运行**的 127.0.0.1:5190 工作台，也是工作台深测的一部分。更改 `portfolio-workbench/` 代码后，旧进程仍在运行时会正确拒绝过期版本；先保存草稿，再正常重启。**启动工作台服务会整理超过限额的历史封面**，禁止为了测试而额外启动一个服务指向正式项目的 `.cover-studio/`；需要隔离复核时为独立的临时项目启动服务，测试完成后关闭并清理副本。
- 本地滚动/缓冲测试依赖单独 Vite 开发环境，不混进生产预览深测。
- 测试结果和截图保存在 Git 忽略的 `.audit/`。只允许按照 [本地缓存维护](./测试与回归维护.md#本地缓存与审计记录安全清理) 的白名单安全清理，保留具恢复价值的历史材料。

历史 ImageKit VPU/缩略图取证时间、账单视图差异与尚未确立的因果关系见本机 .audit/docs-consolidation-20261117/media-incident-evidence.md；现行规范仅要求先阻断自动化媒体请求，异常时再核实真实账单与请求来源。

## 多平台发布与自动化成本

- 2026-11-17 已确认 GitHub `main` 更新可触发 GitHub Pages，以及已连接的 Cloudflare Pages / Vercel / Netlify。测试前用 GitHub 检查记录确认对应发布**状态**，不要为了验收而新建或反复推送空提交。
- Netlify `usage_exceeded` 会导致站点 `503`，这时页面组件不存在不能算作 React 回归失败；也不能重复请求网站测试额度何时恢复。**Netlify 正式站、Deploy Preview 和独立部署 URL 的页面及 Hero 静态视频流量均可能计费**。
- Cloudflare Pages 的桌面 Hero 使用 GitHub Pages 的 Range-compatible MP4；对线上预览执行自动化时，不得通过未拦截的 GitHub Pages 视频流量绕开计费安全约束。常规回归统一本地运行，线上单次媒体确认须先征得批准；详情见 [交接说明](../ARCHITECTURE.md)。
- ImageKit Admin 媒体库与分析页面可能隐式加载视频缩略图，产生 VPU。真实事故证据记录在本节“安全边界”；未经明确批准不得以浏览器批量打开后台页来查账单。

## 维护流程

1. 编辑测试前运行 `npm run check:plan`，确认已有覆盖、间接调用与重复来源。
2. 只修改负责的脚本/清单，不重写无关断言。改动 `package.json` 后运行 `npm run check:repo-layout`。
3. 运行 `npm run check:plan`、受影响专项、`npm run check:project`，保留失败原因及日志；如涉及对外发布再运行对应深测。
4. 比较更改前后队列，除明确说明的重复项外不得静默减少检查。最后运行 `git diff --check`。
5. 合并发布单独进行；测试通过不会自动上传视频、推送 GitHub 或部署 Netlify。


## 本地缓存与审计记录安全清理

### 日常命令

```bash
npm run cache:scan
npm run cache:compact
npm run cache:restore
npm run check:local-audit-cache
```

- `cache:scan`：只读列出五份历史 CSS 对照 JSON 的原始与压缩字节，以及八张可以重跑生成的精选排序 JPEG；不会改文件。
- `cache:compact`：**仅限白名单**：将 `.audit/maintenance-20261114/css-contract/{before,before-new,before-home,after,after-new}.json` 逐一无损压缩为同名 `.json.gz`，生成包含 SHA-256 的 `compressed-baselines-manifest.json`。读取压缩包逐字节校验、记录校验值后，才移走原始 JSON；另清理 `.audit/curated-order/shots/` 中八张可由 `npm run check:curated-order` 再生的指定截图。重复执行不会扩大范围。
- `cache:restore`：根据 manifest 校验压缩包 SHA-256，恢复原始 JSON 文件名与完整内容。旧的 CSS 审计对照脚本需要直接读取 JSON 时，先执行这一命令。
- `check:local-audit-cache`：在独立临时项目检查扫描、压缩、完整哈希、重复执行、恢复、非白名单文件保护；**不会操作真实工作台数据**。

### 永久保护

- `.cover-studio/sessions/`：会话 MP4、旧选帧 PNG、候选 JPG，以及 `session.json`，包括尚未导出或可能需要恢复的画面。
- `.cover-studio/exports/`、`.cover-studio/project-revisions/`、`.cover-studio/association-*.json`、`.cover-studio/source-objects/`：导出、工作台历史、媒体关联与共享对象，不认定为垃圾。
- `assets/`、`src/data/`、`dist/`、`public/`、`node_modules/`：这套命令均不触碰。
- `.audit/mobile-scroll-investigation-20261026/`、`.audit/faststart-ready/`、`.audit/phase1-safe-cleanup-20261112/`、`.audit/docs-history/`、当前 CSS 对照截图和其他审计材料均不在清理白名单。

**不要按体积直接删除 `.cover-studio`。** 部分会话素材使用只读硬链接共享内容，显示出的“重复字节”不代表还能再次释放相同大小。旧帧图即使未列入 `session.json`，也可能属于未完成草稿或恢复证据，因此本轮不自动清理。

### 检查要求

1. 清理前后核对 `git status`、`npm run covers:storage:scan`、正式素材目录指纹。
2. 测试只在隔离临时目录写入，不导出新作品、不改线上 ImageKit URL。
3. 清理工具独立于生产页面，不修改样式、导航、播放器；运行 `npm run check:project` 核验前台与工作台。
4. 若需恢复压缩前的审计文件，使用 `npm run cache:restore`，勿从压缩包中手工覆盖同名正在使用的文件。
